# D278 · AI 报告真网关默认值复跑（2026-11-08）

> 判据一律是**退出码 + 落盘产物**。两轮使用同一命令、同一网关/模型（dsh `127.0.0.1:8326` /
> `qodercn/dfmodel`），唯一变量是**审阅硬上限**（D275 默认 4000 → D278 默认 16000）。
> 全程未改套件断言 / 阈值；第一轮的 4000 数字按 §3.5 原样保留并标注作废。

## 一句话结论

- **第一轮（4000）FAIL / 反证**：超时默认值没有触发（10 请求全 200 / `finish=stop` /
  266797ms），但真实 `五、修复方案` 章 **4696 字符** > 4000 审阅预算 ⇒
  `reviewer:fix:too-long` ⇒ 审阅 **4/5** / `partial=true` / exit 1。
  D275 的 `ai-report-d275-defaults-and-full-review` 据此标 **refuted**。
- **第二轮（16000）PASS**：同一命令下 writer **5/5**、审阅 **5/5**、`partial=false`、
  `failedSteps=[]`、exit 0；11 请求 / 63263 tokens / 348300ms / 报告 51805B。
  `ai-report-d278-review-cap-16000` 升 **verified**。

## 根因与修复

- **根因**：4000 是 D275 按 D266 章节长度（1021~3656）拍的预算，未覆盖真实推理型模型
  在修复章上的输出尺度。超预算时实现按契约**不送审**并标 `partial`（不是静默截断）——
  所以第一轮失败是**如实披露**，不是假绿。
- **修复**：`STEPWISE_REVIEW_MAX_CHARS` 默认 4000 → **16000**（硬上限语义不变：
  >16000 仍不送审、保留原章、标 `reviewer:<key>:too-long` + `partial=true`；
  显式 `AI_REPORT_STEPWISE_REVIEW_MAX_CHARS` 仍优先）。
- **判据**：`server/tests/reportAi.stepwise.d278.guard.test.js` 4 条（默认值=16000、
  4696 字章必须送审、>16000 仍拒绝、显式值优先）；`run-mock.mjs` 不再注入 4000，
  改为走默认值，避免 mock 套件与真实默认值脱节。

## 诚实边界

- **只对 dsh `qodercn/dfmodel` 成立**：不代表公网 / 商业云模型；`/v1/models` 显示名是
  「DeepSeek-Flash · x0.1」，网关未标 v4.1，不得说成「deepseek v4.1 flash 已通过」。
- **单轮实测**：模型输出有波动，章节长度与耗时每轮不同；本轮证明「16000 能覆盖本轮
  全部章节」，不证明所有目标/所有模型都不会超 16000。
- **套件边界**：只验链路事实（网关实调 / 脱敏 / 元数据头 / 逐章审阅 / 边界章节 / 落盘），
  不判报告文风质量。
- **超时默认值**：两轮都没有触发超时（全 200 / `finish=stop`），说明 D275 的
  600s/600s/120s 在**本轮**足够；这不等于所有慢网关都够，慢网关仍应显式调大并用
  `/report/ai/limits` 核对生效值。
- **16000 仍是硬上限**：真正超长章节仍会 `partial=true`，这是有意的失败方向，
  不会为了「全绿」改成节选审阅。
