### 沙箱抓到的发布阻断缺陷（已修，提交 `8d0a85b`）

- **启用 token 后 Web UI 打不开**：`GET /` 返回 `401 需要有效的 API Token`。
  根因：token 中间件只放行 `PUBLIC_READONLY` 精确集合，而 A2 之前默认无 token，这条路径从未被执行到
  ——**只在 Docker/单端口 + 配了 token 的组合下 100% 命中**，开发模式与单测都测不到。
- 修法：按路由段区分——GET 且首段不属于 `{api, sqlmap, scan, exploit}` 视为前端外壳放行；
  其余（含不带 `/api` 前缀的 `/scan/*`、`/exploit/*`、`/sqlmap/*`）仍必须带 token。
- 反向验证：`/scan/aaaaaaaaaa`、`/scan/aaaaaaaaaa/report`、`/api/scan/aaaaaaaaaa` 无 token 均 401。
- 同步新增 CI job `release-smoke`（只依赖 PGlite，不需 MySQL），并把两条断言加进 `security-guardrails`（现 20 项）。
- `v1.1.0` 标签已移到含本修复的提交 `8d0a85b`。

**教训**：A1（CSP 白屏）与本条（token 拦前端）是同一类缺陷——**只在"生产配置组合"下现形**。
此前所有门禁都用开发便利配置，因此需要常驻的"生产配置冒烟"，而不是再加更多单测。
