# runScanLoop 状态收拢设计方案（2026-09-12）

> 前置：拆分三批完成后（1184 → 779 行），`detect` 段（阶段 2 + 3.4，~550 行）判定不拆的理由是
> "引用 37 个主函数变量"。本方案基于**精确读写矩阵**重新分析，结论有变：**不需要把 37 个变量
> 挂到 run 上，只需要把 detect「封边」成"输入 run、输出结果对象"的函数**。

## 一、数据流事实（程序化生成的读写矩阵）

37 个变量 × 6 阶段的读写分析，**跨段写只有 2 个**：

| 变量 | context | discover | detect | wafAdaptive | aggregate | extract+f | 跨段写 |
|---|---|---|---|---|---|---|---|
| blockAdaptiveInfo | · | W | W | R | · | · | 2 |
| schedulerRef | WR | W | R | · | · | · | 2 |
| （其余 35 个） | … | … | … | … | · | · | **≤1** |

典型模式（占 35/37）：**单段产出 → 后续段读取**。例如 detect 段产出
`blockAdaptiveInfo / blockPolicy / blockHits / errorOnlyPoints / fiveXx / highConfWaf /
filterAdaptive / autoRetryEnabled / sharedBaseline / stackedSelected / fullyTestedPoints /
validitySnap / wafVendorsPre / wafAgg …`，供 aggregate 与 finalize 消费。

**重新定性**：问题不是"阶段间靠 37 个散变量通信"（那是拆散视角的错觉），
而是——**detect 单元的 15+ 个产出没有显式的出口，全部以闭包变量形式漏进主函数作用域**。

## 二、设计：封边（envelope），不是拆散

```js
// detect 封边后的形态（示意）
const detection = await detectPhase(run, {
  scheduler, schedulerRef, ctxBase, guard, validity, …   // 输入：基础设施（~12 项）
});
// detection = {
//   foundByPoint, stackedSelected, corroborations?, fullyTestedPoints,
//   blockPolicy, blockAdaptiveInfo, blockHits, errorOnlyPoints, fiveXx,
//   highConfWaf, filterAdaptive, autoRetryEnabled, sharedBaseline,
//   validitySnap, wafVendorsPre, wafAgg, dbms, dbmsVersion, …
// }
// 下游 aggregate/extract/finalize 从 run 或 detection 读取，语义不变
```

关键性质：

1. **detect 内部的 550 行保持局部**——内部几十个中间变量根本不用离开这个函数，
   "37 个变量挂 run"的问题自然消失。
2. **封边是纯搬移**：输入/输出字段与原散变量一一对应，行为等价性验证
   （`diff-reports.mjs`）照常适用。
3. **封边之后，detect 内部获得重构自由**：想拆 WAF 自适应、想整理 per-point 循环，
   都是**局部改动**，不再影响主函数。

## 三、迁移步骤（每步独立提交 + 三件套验证）

| 步 | 内容 | 风险 |
|---|---|---|
| 1 | detect 封边（~550 行搬出 + 输入/输出对象），结果字段逐一对账 | 中（同第二批量级） |
| 2 | context 段并入 run 构造（~145 行，产出全被后续消费，天然是 run 的一部分） | 低 |
| 3 | discover 已封边 ✓，无需动 | — |
| 4 | （封边后的内部整理，可选）detect 内部拆 `perPointDetect` 与 `wafAdaptiveRerun` 两个局部子函数 | 局部风险 |

预期：`runScanLoop` 779 → **~250 行**（纯编排）。

## 四、验证协议（与前两批一致）

1. 全量单测（基线 1735）
2. 靶场全量 r2（基线 18/18 + 7/7 零误报）
3. **报告字段级等价**（`e2e/redteam-lab/diff-reports.mjs`）——封边不改语义，适用

## 五、收益 / 成本 / 何时做

- **收益**：主函数降到纯编排；detect 内部获得重构自由；后续任何检测能力迭代只动一个文件。
- **成本**：约 1 次第二批量级的搬移 + 验证（半天内）。
- **何时做**：不影响正确性，纯迭代速度投资。**当下没有功能压力时再做**；
  若近期要交付/售卖，此项排后。

## 六、明确不做的事

- ❌ 把 37 个变量逐个挂 run（换容器不换结构，白做）
- ❌ 一次性重写 detect 内部（封边前内部耦合无法安全整理）
- ❌ 动 `aggregate` 之后的既有封边（finalize/supplemental/aggregate/extract 已验证稳定）
