## 2. 分级发现

### A. 正确性

**A1. `ERROR_SIG` / `SQL_ERROR_SIG` 两份实现已静默分叉，且漂移守卫看不见 `[事实]`**

- 两份定义：`server/src/engine/payloads/index.js:345`（`ERROR_SIG`，ErrorDetector 判「响应体是数据库报错」）与 `server/src/core/scanValidityGuard.js:94`（`SQL_ERROR_SIG`，判 selfInflicted 是否计入 serverErrRatio）。
- scanValidityGuard.js:91 注释自称「补齐为 ERROR_SIG 的同集」，但逐项比对后**并不相等**：
  - 仅 `ERROR_SIG` 有：`unterminated quoted string`（PG 引号未闭合裸形态）、`Unclosed quotation`（大小写等价，略）、`HSQLDB.*(?:error|exception)`、`Derby.*SQLException`、`Informix.*(?:error|exception)`、裸 `SQLite3`（vs `sqlite3\.`，后者更窄）。
  - 仅 `SQL_ERROR_SIG` 有：`PG::`、`unrecognized token`。
- 守卫 `server/tests/errorSig.specificity.test.js` 只钉「固定 REAL_ERRORS / GENERIC_PAGES 语料两侧一致命中/不命中」——**不校验集合相等**，分叉项无任何覆盖。
- 影响方向（两侧都有，都不报错）：
  - PG 裸 `unterminated quoted string`、HSQLDB/Derby/Informix 三种报错形态 ⇒ ErrorDetector 计入错误命中，但 validity guard **不归 selfInflicted** ⇒ 计入 serverErrRatio ⇒ 可能被判 `target_error`/「结论不可信」。**这正是 2026-10-03 P1-B 修过的那条静默误判链的窄版复活**（extractvalue 那版已修，这几条漏网）。
  - `unrecognized token`（SQLite 高频）⇒ 反向：guard 归 selfInflicted 而 ErrorDetector 不计，真实 target_error 可能被掩盖。
- 修法（二选一）：① 一侧 import 另一侧，单源；② 加**集合相等守卫**（把两个正则的 source 串拆分排序后比对，注释剔除），与既有漂移守卫并排。
- 未验证边界：运行时影响面未实测（需真库构造三种报错形态看 verdict 变化）；上述方向为源码比对 + 机制推断 `[推断]`，A1 的「分叉存在」是 `[事实]`。

**A2. CLI 用户完全无法开启 NoSQL / OOB 两个默认关通道 `[事实]`**

- `server/bin/cli/args.js` 无 `noSql`/`oob` 任何旗标（grep 零命中）；`server/bin/cli/configFile.js` 的档案合法键集（parseArgs 默认键 ∪ 动态键登记表）也不含这两组 ⇒ **`--config {"oob":{"enabled":true}}` 会被当未知键拒绝启动**。
- 而 UI（`src/shared/constants.ts:53/139/142`，面板有「带外注入(OOB)」分组）与 REST（`server/src/api/scanRoutes.js:64` 白名单）都可达。
- 后果：走 CLI / 脚本 / `--config` 复扫配方的用户，**默认扫不到 NoSQL/GraphQL/SSTI 与 OOB 整条通道面**，且没有任何东西变红（defaults.js:292-293 明写「即使 techniques 含 oob，也需 oob.enabled 才启动接收端」）。
- 顺带：`defaults.js:313` 注释自承 `noSql.concurrency`「既没有默认值可回落，也没有任何守卫」。

**A3. `db-json` 格式在 CLI 与 MCP 双缺，且 CLI 未知格式静默回退 JSON `[事实]`**

- `server/bin/cli.js:73-85`（`formatReport`）只认 json/html/csv/markdown/md，未知格式**不报错、回落 JSON** ⇒ `--format db-json` 会写出一个名为 `report.db-json` 的普通 JSON（「传了没生效」形态，本仓红线）。
- MCP `get_report` enum（`server/src/mcp/tools.js:197`）同样缺 `db-json`。
- 拖库 JSON 目前只有 REST / UI 拿得到。CLI help（`help.js:218`）也只写 json|html|csv|markdown，漏了已实现的 sarif。

### C. 性能（已量化）

**C1. tamper 插件循环内重复编译正则 `[事实+量化]`**

- `server/src/core/tamper/plugins/keyword2hex.js:17-20`：每次 `transform` 对 30 个关键字逐个 `new RegExp`。
- 实测（本机 node 22，20000 次调用）：**15.87 µs/call**（317ms/2 万次）。复现：

```bash
node --input-type=module -e "
import { keyword2hex } from './server/src/core/tamper/plugins/keyword2hex.js';
const p = \"1' AND SLEEP(5) UNION SELECT CONCAT(username,0x3a,password) FROM users WHERE id=1-- -'\";
const N=20000; let t0=process.hrtime.bigint();
for(let i=0;i<N;i++) keyword2hex.transform(p,{});
console.log('us/call =', Number(process.hrtime.bigint()-t0)/1e6/N*1000);"
```

- 同族还有 8 个（`keyword2decimal.js:15`、`keyword2hexall.js:21`、`keyword2octal.js:14`、`keyword2unicode.js:15`、`keywordSplit.js:21`、`randomboundary.js:16`、`safedog.js:55`、`mssqlnosemicolon.js:17`）；其中 `keywordinterleave` 位于**默认就会走的**自动重跑路径（`wafRecommend.js:91-95` FILTER_BYPASS_CHAINS）。
- 判断：不是瓶颈，是白烧（一次扫描 tamper 应用在万级 ⇒ 百 ms 级浪费）；修法为零行为变化的模块级预编译。⚠️ 预编译后必须复跑 `tamper:parity` 与 `tests/tamperKeywordCoverage.test.js`（keyword2hex ⊆ keyword2hexall 的包含关系有守卫）。

**C2. `sessionSecret` 缓存顺序颠倒，条件性 N² 读文件 `[事实+推断]`**

- `server/src/core/sessionSecret.js:62-66+73-75`：`getKey()` 先调 `secretKeySource()`（内部 `readApiTokenMaterial()` 读 `SCAN_API_TOKEN_FILE`）**再**查缓存；`sessionStore.js:156-158` 的 `_snapshot()` 每个注入点调一次 ⇒ N 个点 ≈ N² 次同文件读。
- 触发条件 `[推断]`：仅当设置了 `SCAN_API_TOKEN_FILE` 的用户命中；真实部署比例未知，未量化。
