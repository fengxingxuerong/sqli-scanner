## 三、本批落地

### 3.1 paramMine —— Arjun 式参数挖掘（旗舰项）

**解决的问题**：TargetParser 只能发现「已出现在 URL/body/表单里的参数」。真实目标常见的
「隐藏参数才进 SQL」（`?debug=1` 才回显报错、`?sort=` 才进 ORDER BY）此前整体漏检——
假阴性是扫描器最贵的一类错。

**算法**（吸收 Arjun 思想，请求预算内收敛，`server/src/engine/discovery/paramMiner.js`）：

1. baseline：不带探针取基线响应（status + 长度）；
2. canary：发 1 个哨兵参数——目标无条件回显输入时反射信号失效，退化为纯响应差异信号；
3. 分组：内置字典（`discovery/paramWordlist.js`，~260 条高频参数名）按 30/组探测，
   命中信号 = 标记回显 或 状态码变 或 长度差 ≥ 24；
4. 二分：命中组对半拆分逐层收敛；
5. 单参复核：换新标记单独确认（剔除组间串扰）。
   防噪护栏：>60% 组命中 → 判目标过噪，放弃本次挖掘；请求预算硬顶 150。

**边界**（防「发出去是畸形请求」）：

- 只挖主目标 URL 一次，不随爬虫扩散（crawler 新 URL 的参数已被动收录）；
- 载体只认 GET/HEAD query 与 POST/PUT/PATCH urlencoded；JSON/XML/multipart 跳过
  （注入侧对这类载体没有「新增键合入」的渲染路径）；
- 用户精确标记（值尾 `*`）与 onlyPoint 单点重测时跳过（显式意图优先，预算不白花）；
- 挖掘失败只 log 不抛：增强能力不阻塞主扫描；
- 全部探测走 per-scan client：限速桶 / SSRF / scope 逐请求校验照常生效。

**接线清单**（每个键的完整管道，防「引擎有、某层收不到」）：

| 层 | 文件 | 改动 |
| --- | --- | --- |
| 引擎 | `engine/discovery/paramMiner.js` + `paramWordlist.js`（新增）；`TargetParser.js` 6.6 步 | 挖掘 + 合成注入点（`mined: true` 溯源标记，originalValue `'1'`） |
| REST | `api/scanRoutes.js` KNOWN_CFG_KEYS + `api/scanGuard/scalarsCore.js` | 白名单 + `pickBool` 严格布尔（`1`/`"true"` 不得误开，hex/flushSession 同口径） |
| CLI | `bin/cli/args.js`（默认值 + `--param-mine`）+ `config.js` + `help.js` | 开关透传 + 文档 |
| 前端 | `shared/constants.ts`（SCAN_CONFIG_KEYS + 值类型 + 默认值）、`shared/types.ts`、`scanConfig/CrawlerSection.tsx`、i18n zh/en | 爬虫分段新增开关（挖掘不依赖爬虫，故不置灰；默认关） |

**测试**（`server/tests/paramMiner.test.js`，11 用例全绿）：本地 http server 模拟五种目标——
反射型命中（24 请求收敛出 debug）/ 静态页零发现 / 全回显防噪 / 预算硬顶 / POST 载体 /
existingParams 去重；集成侧：discover 合成点位、默认关闭零请求、JSON 跳过、精确标记跳过、
onlyPoint 跳过。前端契约（`scanConfig.contract.test.ts` 20 用例）覆盖键管道。

### 3.2 扫描预设 quick / standard / deep（ZAP Attack Strength 思路）

`src/shared/scanPresets.ts`：预设 = **既有键的 patch 快照**（不引入新配置键，后端零改动）。
常驻 ScanConfigPanel 折叠头（一击切换，不必展开拨 5+ 控件）；patch 语义（只覆盖声明的键，
用户手填的 proxy/scope/extractScope 原样保留）。

- **快速面检**：level 1 / risk 1 / union+error / 爬虫关 / 预筛全开——最少请求量摸一遍面；
- **标准扫描**：与 DEFAULT_CONFIG 检测强度面对齐（测试钉死防漂移）；
- **深度审计**：level 5 / risk 3 / 全技术含 inline Q / 爬虫+表单 / 关预筛——宁可慢不可漏。

刻意不含 paramMine：挖掘会发额外探测请求，属显式 opt-in，不被预设顺带打开。
测试：`src/tests/scanPresets.test.ts`（6 用例）钉住「键在白名单 / 类型一致 / 数值在
clamp 区间 / standard 与默认对齐 / 不含 paramMine」。

## 四、评估后不吸收（留痕防重复 triage）

| 项 | 理由 |
| --- | --- |
| **ETA 进度** | 进度事件链（point_discovered → processedCount）无时间戳；且时间盲注点单点可达数分钟，按「点完成速率」估 ETA 会系统性误导。要做得先改事件层埋点，收益/侵入比不划算 → future |
| **chunked / skip-urlencode** | 需在 httpClient 层改造分块传输编码与手工 query 序列化，侵入大；真实受益场景（畸形 WAF）在 waf-lab 靶面占比小。已有 tamper 链覆盖大部分绕过需求 → 暂缓 |
| **JS 被动参数提取** | 需 crawler 解析 JS body + 提取规则 + 去重池，是独立一批的量；且与 paramMine 互补而非替代（主动已可覆盖大部分）→ future |
| **超大参数字典** | Arjun 26k 条在预算硬顶 150 下只会稀释收敛（预算先于字典耗尽）；本仓定位是注入扫描器而非专职发现器，扩量场景建议先跑 Arjun/x8 再回填目标 |
| **sqlmap 代码级移植** | GPLv2 vs 本仓 MIT，许可证不兼容。**只吸收思想与行为语义，零代码复制**（本批及既往批次的既定纪律） |
