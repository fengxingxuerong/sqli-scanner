## 一、本批已落地（4 × P0）

### P0-1 拖库「0 行」恒真对照（空结果 ≠ 空表）
- **问题**：UNION 回显被 WAF/类型限制拦死时，非空表提取 0 行 → 报告交付「空表」，客户对原库一核即翻车。
- **修法**：`Extractor.dumpData` 主循环 0 行时补 **1 次**行存在性探针（按方言：`SELECT 1 FROM t LIMIT 1` /
  MSSQL `TOP 1` / Oracle `ROWNUM=1` / DB2 `FETCH FIRST`）：探针有行/异常 → 标「未确认」；无行 → 真空表静默。
- **接线**：`onUnconfirmedEmpty` 回调沿 `dumpData → dumpDatabase → dumpAllDatabases → extractAll → mergeExtracted`
  全链透传，聚合进 `data.meta.dumpUnconfirmed`，并写入 `report.summary.constraints`（HTML/Markdown 首屏可见）。
- **文件**：`engine/Extractor.js`、`engine/extractScope.js`、`engine/scanRunner.js`
- **验收**：`tests/extractor.emptyConfirm.test.js` 6 例（探针有行/无行/异常/非空零请求/方言 SQL 形状/聚合 meta）。

### P0-2 tamper 幂等声明 → 可执行守卫
- **核实**：现网 227 个插件**无任何** `idempotent` 声明（上一批文档所指 blindbinary 声明已不在）——
  风险从「声明不实」变为「无守卫可言」，未来加插件可以随意乱标。
- **修法**：
  - `TamperRegistry.list()` 透出 `idempotent` 声明（UI/API 可见）；
  - `resolve()` 对链中重复出现的显式 `idempotent:false` 插件告警（重跑/链式损坏场景）；
  - `blindbinary` 经验证（二次应用为空操作）声明 `idempotent: true`；
  - 新守卫测试：全量插件双应用不抛错（稳健性底线）+ 声明 `idempotent:true` 者必须 `f(f(x))===f(x)`。
- **文件**：`core/tamper/TamperRegistry.js`、`core/tamper/plugins/blindbinary.js`
- **验收**：`tests/tamper.idempotency.test.js` 3 例。

### P0-3 `--invalid-bignum / --invalid-logical / --invalid-string`（缓存/静态页噪声规避）
- **问题**：布尔盲注的「有效值」前缀命中 CDN/应用层缓存或与静态页同形 → 真/假无差异 → 误判不可注入
  （真实站点布尔盲注最常见失败原因，sqlmap 三开关本项目缺位）。
- **修法**：新模块 `engine/invalidValue.js`（`invalidize`/`applyInvalidValues`），scanRunner 在预筛选前
  统一改写 `point.originalValue` → 探测/检测/提取全链路（fillPayload `{ORIG}`、probeBoundary 基线、盲注提取 base）一次生效。
  语义与 sqlmap 对齐但真值保守化：`logical` 取恒真等值式 `n=n`（sqlmap 的 `1=2` 会破坏「基线≈真页面」前提）。
- **接线**：CLI 三开关（互斥）；REST `invalidValue`（defaults → KNOWN_CFG_KEYS → sanitizeStart 三处同步，守卫测试锁死）。
- **文件**：`engine/invalidValue.js`（新）、`engine/scanRunner.js`、`config/defaults.js`、`api/scanRoutes.js`、`bin/cli.js`
- **验收**：`tests/invalidValue.knownPoint.test.js` + `tests/cli.invalidKnown.test.js`；configWhitelist 双守卫全绿。

### P0-4 `knownPoint` 已知注入点直通
- **问题**：手工确认的点仍要跑预筛选探针（3 请求/点）+ 闭合探测（13 候选并发）+ 全技术位扫描。
- **修法**：新模块 `engine/knownPoint.js`，`config.knownPoint = { param, quote?, paren?, techniques? }`：
  - 匹配点打 `knownPoint=true`：预筛选跳过探针（但**必须并入返回集**，不丢点）；
  - `quote/paren` 给定时闭合形态写死，`probeBoundary` 短路（13 候选 → 1 基线请求；基线保留以学习 `_baselineTitle`）；
  - `techniques` 作为扫描级技术位交集（与 `config.techniques` 双重交集，`_selectedTechs` 唯一过滤入口生效）。
- **接线**：CLI `--known-point "param=id;quote=';paren=);techniques=union,error"`（键值对用 `;` 分隔——
  逗号版实测 `techniques=union,error` 的值被截断成 `union`，`error` 被当成新键）；REST `knownPoint` 对象透传（param/quote/paren 截断限长、techniques 白名单过滤）。
- **文件**：`engine/knownPoint.js`（新）、`engine/scanRunner.js`、`engine/ScanManager.js`、`engine/Detector.js`、`api/scanRoutes.js`、`bin/cli.js`
- **验收**：`tests/invalidValue.knownPoint.test.js`（probeBoundary 短路 1 请求 + 普通点 14 请求回归对照 + prefilter 并入返回集 + 技术位交集 + REST 透传）。
