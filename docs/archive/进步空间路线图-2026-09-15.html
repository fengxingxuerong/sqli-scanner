七批优化把「检测召回、拖库正确性、利用链闭环、工程正确性」四个维度补到了真机可验证的水位。剩下的进步空间不再是「补缺陷」，而是三层跃迁：对抗纵深（真实 WAF）、覆盖广度（国产库与协议面）、架构天花板（分布式与吞吐）。

§ 01

P0 —— 实战价值最高（下一程主攻）

1 · 真实 WAF 实测矩阵CRS 战绩无法外推到云 WAF —— 这是交付可信度的最大缺口
  • 雷池（SafeLine）社区版本机部署：语义分析引擎，与 CRS 关键字正则是两个物种；开源可自架，是「无 Docker 也能真测云级 WAF」的最短路径（Linux 主机或虚拟机）
  • 安全狗 / 云锁免费版：国内交付环境最高频，装 Windows 靶机即可实测（tamper 自动选链对关键字族 vs 语义族的差异会被真实暴露）
  • 阿里云 WAF / Cloudflare 免费档：需要公网入口 + 授权域名，按 pentest-lab 方法论做 off/on A/B + 手工绕过对照
  • 验收：WAF 实测矩阵写入 run-all（可跳过标记），报告的 WAF 交战章节从「实验室数据」升级为「真实环境数据」
2 · 分布式扫描队列Scheduler 目前是内存态单机 —— 批量资产扫描的架构天花板
  • BullMQ + Redis 任务队列：scan 任务入队、多 worker 消费、断点续扫跨进程恢复（sessionFile 已有基础，缺的是跨进程语义）
  • 限速桶随任务走：TokenBucket 已按 scanId 隔离，分布式化后需 per-worker 全局配额（防止 3 个 worker × 10 req/s 变 30 req/s 打爆授权书范围）
  • 验收：3 worker × 20 目标并发，结果汇聚与单机一致，scope 约束在分布式下依然逐跳硬约束
3 · 国产库真机化（DM8 / TiDB）政企信创交付的真实需求，template-only 里最有价值的一块
  • DM8（达梦）：Windows 安装包直接装（MSSQL 同款路线），方言语法独立（兼容 Oracle 风格但差异多），国产化项目渗透几乎必遇
  • TiDB：MySQL 协议兼容，单二进制零安装——成本最低、可先行；重点验证 MySQL 方言模板在 TiDB 的差异面（information_schema 差异、函数支持差异）
  • 验收：各建靶场一套（检测 + 拖库），dbmsEvidence 升级对应档位
§ 02

P1 —— 引擎内核与协议面

4 · 盲注提取再提速字节级并行二分已做到 K 倍；位平面法还有 4-8 倍空间
  • 位平面提取：现一次请求取一个字节（0-255 二分 ≈ 8 次请求）；BIT_COUNT+位掩码法一次请求取 8 位，理论上再省 ~4 倍请求（对时间盲注场景 = 直接决定能不能在授权窗口内拖完库）
  • SPRT 顺序检验替代固定 μ+zσ：时间盲注判定用序贯概率比，可在置信度不变下再降 20-40% 请求
  • predictOutput 智能化：前缀树 + 常见值字典（表名/列名预猜）在缓存未命中时也能跳过完整二分
5 · 攻击面发现（爬虫 / --crawl / --forms）sqlmap 有、本项目还没有的整块能力
  • 受限爬虫：scope 内同域爬取 + 表单自动发现 + 参数模糊化（--forms 已有表单点捕获，缺主动发现）
  • Burp/ZAP 请求导入：从代理历史直接建 target（真实交付里注入点大多是人工浏览发现的，爬虫只是兜底）
  • union-char / --hex / --no-escape：三个保留接口落地（差距清单已标注未实现）
6 · 认证与协议面补齐Windows 域与现代 Web 认证
  • Negotiate/Kerberos：MSSQL 真机已就绪，域内目标（sa 走域账号）是自然延伸；NTLM 已自实现 DES，Kerberos 可走 SSPI 桥
  • OAuth2 Bearer / JWT 自动续期：token 过期自动刷新（与 CSRF 刷新同构，csrfKeeper 模式可复用）
  • Oracle os-shell（Java Source）真机闭环：环境已就绪（26ai Free + SYS），补最后一条利用链
§ 03

P2 —— 工程与交付质量

7 · CI 真机化 + 前端 e2eCI 目前跑不了 20 套真机靶场（依赖本机四库）
  • GitHub Actions services 容器：mysql/pg/mssql 官方镜像做 service container，CI 里跑大部分靶场（Oracle 用 gvenzl/oracle-free 镜像）；本机四库作为 full 套件的补充
  • Playwright 前端 e2e：扫描下发 → SSE 进度 → 报告导出的 UI 主链路目前无浏览器级回归
  • 覆盖率阈值硬门禁：wrapper 已有，补数字基线（branches/lines 门槛进 CI fail 条件）
8 · 报告与生态互操作markdown/html/csv + CVSS 已有；差的是「接入客户工作流」
  • SARIF 输出：直通 GitHub Security / DefectDojo（甲方安全平台对接的通用货币）
  • PDF 导出：正式交付物形态（当前 html/csv/markdown，客户合同常要求 PDF）
  • 性能基线回归：perf-baseline.json（盲注吞吐/并发 QPS/union 延迟）进 CI，防「优化引入回归」
9 · 仓库与协作收口多会话并行开发的遗留整合
  • 223 文件未提交改动收口：并行会话的 tamper meta 重构（meta 注释 + cli.js 拆分）在制品，需 review 后合入
  • 架构守卫基线刷新：arch-baseline.json 随拆分更新，防止「拆分后文件悄悄长回去」
  • union-char/hex/no-escape：文档口径与实现状态对齐（保留接口标注已做，剩余是落地）
§ 04

优先级总表

#方向实战价值工作量验收方式
1真实 WAF 实测矩阵（雷池自架 / 安全狗 / 云 WAF）交付可信度的最大缺口中WAF 矩阵入 run-all + 报告 WAF 章节真实数据
2分布式扫描队列（BullMQ）批量资产场景架构天花板大3 worker 并发隔离 + scope 分布式硬约束
3DM8 / TiDB 真机化信创交付刚需中两套靶场 + evidence 升级
4位平面盲注提取时间盲注吞吐 4 倍中perf 基线对比 + 正确性回归
5受限爬虫 / Burp 导入攻击面发现自动化中--crawl 端到端靶场
6Kerberos / OAuth2 续期域环境与现代 Web中NTLM 同款 e2e 模式
7CI services + Playwright回归安全网小-中CI 跑真机靶场子集 + UI 主链路
8SARIF / PDF / perf 基线交付与防回归小格式校验 + 门禁生效
9并行会话改动收口协作卫生小review + 合入 + arch 基线刷新
Selection Logic 排序依据是渗透交付的五要素：召回（别漏——靠覆盖广度与检测深度）、误报（别虚——靠安全对照与诚实分级，已达标）、吞吐（别慢——位平面 + 分布式）、合规（别出事——scope/限速已达标，分布式化后要重点回归）、交付（报告好用——SARIF/PDF）。P0 三项都是「不做就上不了真实战场」的级别；P1 是「做了在真实战场明显更强」；P2 是「工程复利」。

明确不做（保持边界）

  • os-pwn / meterpreter / 横向移动 —— 超出注入检测工具的合规边界
  • --eval 动态代码 —— 安全考虑，仅 sqlmap 桥接透传
  • 未授权目标的任何能力强化 —— scope 约束是产品的一部分

已达标无需再投入

  • 攻击工具自防御纵深（SSRF/scope/脱敏/恒时比较）
  • 诚实性工程（inconclusive verdict / evidence 分级 / 守卫测试）
  • 主流库利用链闭环（MySQL/PG/MSSQL 四条路径真机验证）
