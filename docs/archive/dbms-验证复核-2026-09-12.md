### 多引擎复跑命令（H2/HSQLDB/Derby）

```bash
cd D:/projects/sqli-scanner
ENGINE_JARS="D:\engines\jars\h2.jar;D:\engines\jars\hsqldb.jar;D:\engines\jars\derby.jar;D:\engines\jars\derbyshared.jar" \
  NO_PROXY=127.0.0.1 node e2e/multi-engine-lab/verify.mjs
```

前置：Java 21（本机 Temurin 21.0.10 ✓）、四个 jar（`D:\engines\jars\` ✓）、无外部 DB 服务（真实 JDBC 内存库）。

实测输出（2026-09-12）：

```
h2       num: off=2 on=2  str: off=0 on=0  blind: off=2 on=2
hsqldb   num: off=2 on=2  str: off=0 on=0  blind: off=2 on=2
derby    num: off=2 on=2  str: off=0 on=0  blind: off=2 on=2
安全对照误拦/误报：无 ✅
```

> 注：README 把 H2/HSQLDB/Derby 描述为"仅布尔通道"，实测 `num`/`blind` 场景各命中 **union + boolean**
> 两条通道——即实际能力**强于**文档声明（文档偏保守，不是夸大）。

### 缺项说明：MariaDB

`e2e/multi-engine-lab/mariadb-verify.mjs` 连接 `127.0.0.1:3308`（可用 `MARIADB_PORT` 覆盖），
本机 3308 无监听（3306 是 MySQL），故**无法当场复现**。README 中该项引用的是
2026-09-10 在装有 MariaDB 11.4.13 的环境下取得的结论。

补齐方式（任选）：
1. 本地起 MariaDB 实例并监听 3308 → `node e2e/multi-engine-lab/mariadb-verify.mjs`；
2. 或把该项在 README 中改标为"历史环境验证（当前环境无 MariaDB，未复现）"，避免读者误以为随时可复跑。

**在补齐之前，MariaDB 那一行应视为"待复核"**——这正是 README 自己给 ⛔ 档位定义的措辞。
