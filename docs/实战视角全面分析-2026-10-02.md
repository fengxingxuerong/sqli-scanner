# 实战视角全面分析 —— 渗透工程师视角（2026-10-02）

> 定位：与 `全方位优化建议-2026-09-30.md`（全栈工程视角）互补的另一把尺子——
> 把自己当成拿到授权书、要在两周交付窗口里打一个真实 Web+API 目标的渗透工程师，
> 沿作业链逐环节评估：这个工具能不能带进现场、哪些环节能打、哪些环节会掉链子。
> 所有结论均带代码证据（file:line），未查实的不写。
> 调研方法：三路并行代码走查（报告与 PoC / 接入与认证 / 检测与利用）+ 既有靶场证据。

## 0. 执行摘要

**总体判断：对「授权范围内、经典 HTTP 通道、MySQL/MariaDB/PG/MSSQL/SQLite/Oracle 六库」
的注入作业，这是一把能真用进现场的扫描器，不是玩具**——检测判定工程（基线 RTT 补偿、
二次确认、动态内容归一化）、交付级 PoC（逐 payload 可重放三件套）、安全护栏
（scope fail-closed / EXPLOIT_ENABLED / confirmDestructive）三处达到甚至超过 sqlmap
的同位体验。作业链上真正的断点集中在：**SPA/JS 渲染目标接不进**（爬虫是正则 HTML）、
**认证只有静态注入没有登录编排**（token 过期就得人工重扫）、**12 个方言库是
template-only 的纸面能力**、**交付格式里看不到跳过统计**（甲方问"测全了吗"对外格式答不上）。

| 环节 | 实战评级 | 一句话 |
| --- | --- | --- |
| 目标接入（5 通道） | ★★★★★ | Burp→XML→-m 批量主路径通，集合格式识别齐全 |
| 认证与会话 | ★★★☆☆ | 静态注入+jar+csrf+保活好用；无登录编排；NTLM 引擎有 CLI 卡死 |
| 注入点发现 | ★★★★☆ | 10 个来源含 paramMine；SPA 目标基本抓瞎 |
| 检测 | ★★★★★ | 9 检测器 + 判定工程 + WAF 闭环，强于 sqlmap 同位 |
| 利用与后渗透 | ★★★★☆ | 六库全链含写回闭环验证；12 库利用未实现 |
| 报告与交付 | ★★★★☆ | PoC 可重放是全仓最强项；跳过统计不进交付格式 |
| 复测与工程化 | ★★★☆☆ | 单点重测/续扫有；无变更差异扫描、无可观测性 |

## 1. 作业链逐环节评估

### 1.1 目标接入 —— 五条通道，主路径全通

- `-u` 单 URL（help.js:25）；`-r` 请求文件三层：单报文（requestFileParser.js:1-10）、
  集合格式自动识别 har/burp-xml/postman/openapi/openapi-yaml/raw
  （requestCollectionParser.js:26-58，Postman 支持嵌套 folder + 4 种 body mode、
  含真实 multipart 重建，:218-295）、YAML 走零依赖 yamlLite（第四批，:419-452）。
- `-d` 直连（mysql/sqlite 内置驱动，dbDrivers.js:25,80,174；scheme 推断
  mysql/postgres/mssql/oracle/sqlite，:218-231）；`-m` 批量（batchTargets.js:41-137，
  故障隔离并发池 batchPool.js）+ `-l` 代理日志批量。
- **接不进的**：curl shell 命令文本、Charles 等非 Burp XML、含 `{{var}}` 未处理的
  Postman 集合、带 multipart 的批量集合（需逐条 `-r`）、Oracle/MSSQL 直连
  （驱动需自备，开箱只有 mysql2）。
- ⚠ 集合格式在 `-r` 下**只取第 1 条**（help.js:22）——多请求集合必须走 `-m`，
  现场新人最容易踩的第一颗钉子。

### 1.2 认证与会话 —— 三件套好用，编排缺失，一处自相矛盾

- CookieJar（RFC 6265 简化实现，cookieJar.js:1-13，每扫描一个 jar）、csrfKeeper
  （13 个常见 token 名自动探测，:23-29）、safeUrlKeeper 保活（跨源剥离凭据，:25-33）、
  Digest（RFC 7616 含 SHA-256 协商，digestAuth.js:1-11）齐备。
- **NTLM 自相矛盾**：引擎有完整 NTLMv1 三步握手（ntlmAuth.js 自带 MD4+DES-L 实现，
  ntlmHandshake.js 按 host 缓存状态），但 CLI `parseAuth` 只认 basic|digest，
  `--auth-type=NTLM` 直接抛「NTLM 需 Type1-3 协商未实现」（args.js:555）——
  **报错文本与引擎现状相矛盾，是陈旧卡死，不是能力缺失**。
- **无登录编排**：全仓无 login 表单提交逻辑；会话失效只能检测不能自愈
  （scanValidityGuard.js:47 登录跳转签名、:426-427 连续 401 判失效）。
  现场 coroutine：token 一小时过期 → 人工重取 cookie → 续扫。

### 1.3 注入点发现 —— 十个来源，唯 SPA 缺席

URL query / body / JSON 叶子 / XML·SOAP 叶子 / cookie（level≥2）/ header
（level≥3，--test-headers 强制）/ path 段（--test-path）/ 表单爬取 / 链接爬虫 /
paramMine 参数挖掘（本日第五批）——来源清单本身已超 sqlmap 单机默认面。
爬虫是纯正则 HTML（crawler.js:13-20 仅 6 组标签属性；深度钳 0-3、同 host、去 hash 去重、
默认 50 页），**playwright 只在 devDependencies 且仅 e2e 引用（package.json:124），
引擎零引用**——React/Vue SPA 爬出来是空壳 index.html，`/api/*` 全丢；
JS bundle 里的接口路径、HTML 注释遗留接口均不提取。这类目标只能靠手工抓包
导 HAR/Postman 走集合入口补齐（好在 1.1 的入口面够宽）。

### 1.4 检测 —— 本仓相对 sqlmap 最强的两处之一

9 个检测器与 sqlmap 技术面对齐（union/error/boolean/time/stacked/oob/second_order/inline
+ NoSQL/GraphQL/SSTI 合一补充趟）；判定工程重于 sqlmap：基线 RTT 补偿 + 串行复验
（DBFingerprinter.js:205-228）、布尔 855 行含动态数值归一化（BooleanBlindDetector.js:12-20）、
NoSQL 二次确认防抖动（NoSqlInjectionDetector.js:77-84）。
DBMS **诚实三档**（dbmsEvidence.js:19-42）：verified 六库（MySQL/MariaDB/PG/SQLite/
MSSQL/Oracle，各有真机靶场）/ partial 三库（H2/HSQLDB/Derby 仅布尔）/
**template-only 九库**（方言 payload「未经真实环境验证」是 payloads/index.js:55-70 的
自我声明）。
WAF 体系：62 家识别（含安全狗/云锁/宝塔类国产，wafRules.js:7-133）、228 个 tamper
（sqlmap 上游 70 的 parity 基线有守卫）、探针验链 + 定向变异搜索（chainVerify.js:36-40）、
CRS 官方回归集校准保真度 99.6%（acceptance crs-fidelity）——
「识别→推荐→验链→定向生成」闭环是 sqlmap 没有的。

### 1.5 利用与后渗透 —— 六库能打穿，且两处比 sqlmap 严谨

- fileRead：MySQL LOAD_FILE / PG pg_read_file / MSSQL OPENROWSET BULK /
  Oracle UTL_FILE 全链（CREATE DIRECTORY→GTT 物化→4000 字节分段回显，fileRead.js:35-90）。
- fileWrite：MySQL OUTFILE（无堆叠时 UNION…INTO OUTFILE 兜底，fileWrite.js:45-58）/
  PG COPY TO / MSSQL echo>；**写后读回闭环验证**（:27-31，修过 wrote:true 实际没落盘的
  假成功）——sqlmap 没有这层。
- osShell：PG COPY FROM PROGRAM、MSSQL xp_cmdshell（结果空且 xpAutoEnable≠false 时自动
  sp_configure 启用，osShell.js:57-84）、MySQL sys_eval 编码归因、Oracle Java Source
  Runtime.exec（:193-225）。
- UDF（MySQL/PG，hexPath 全链含 secure_file_priv 探测校验，udf.js:36-46；
  **不内置 .so/.dll，需自备**——sqlmap 内置 data/udf，这是现场差距）、registry（MSSQL）。
- 护栏链是全仓最重的：EXPLOIT_ENABLED + authorized + 独立限速（exploitRoutes.js:347-361）、
  scope 未声明 fail-closed、写类必须 confirmDestructive（:109-121）、高危池默认隔离
  （defaults.js:56-63）——适合授权交付，防手滑能力远超 sqlmap。
- **纸上库**：DB2/Sybase/Firebird/Informix/H2/Access/HSQLDB/Derby/MonetDB/ClickHouse 十库
  capabilities.js:65-137 明示 file/osShell/udf 全部 `supported:false`——检出也打不穿。

### 1.6 报告与交付 —— PoC 可重放是最强项，跳过统计是交付盲点

- 五格式（JSON/CSV/Markdown/SARIF 2.1.0/HTML，无 PDF）同源 buildDelivery 防漂移；
  漏洞条目带 CWE/OWASP/CVSS+vector/按通道修复建议。
- **PoC 三件套**（pocBuilder.js:264-278）：结构化请求**复用引擎 buildInjectionRequest**
  （「PoC 与扫描时真实发出的请求必须逐字节一致」，:17-18）+ curl 单行（shell 注入加固，
  :61-73）+ 原始报文（与 requestFileParser 互为逆运算，可 sqlmap -r 导入）。
  **逐 payload 展开一条 PoC**（reportPoC.js:168-212），实测产物见 deliverables-demo/report.md。
- 时间线/统计：请求计数细项（counts 含 injection5xx）、结论可信度三态
  （inconclusive/no_vuln/vuln，「有漏洞却写未检出」的自相矛盾已修）、
  **能力抑制清单**（constraints：高危池被抑制/cookie 因 level 不够根本没变成注入点——
  同类工具罕见）、WAF 交战记录、定库证据等级（verified/partial/template-only）。
- **交付盲点（查实）**：`skippedPoints`（prefilter/validationSkip 跳过的点及原因）
  在 services/ 四个报告模块**零渲染**——只有 JSON 整包和前端 ReportPage（skipReason 逐点
  标注）可见。**导出给客户的 md/HTML/CSV/SARIF 里，「为什么没测」不可见**。
- AI 报告：三角色流水线（analyst→writer→reviewer）+ 429 冷却 + prompt 抗注入 +
  host 打码，护栏认真；但 writer 产出的 PoC 用占位 Host（ReportAI.js:233-238）——
  **是管理层叙事，不是复现证据**，交付口径必须写清楚。

### 1.7 复测与工程化 —— 半自动够用，差异扫描缺失

onlyPoint 单点重测（location:param 匹配，调参后只重跑一个点）、session 续扫
（--resume/flushSession/freshQueries）、批量故障隔离（单目标失败不中断整批）、
台账保留策略。缺：**变更差异扫描**（两次扫描间「新增端点/参数」自动圈出重测）、
`/api/metrics` 可观测性（09-30 审计已列 P1，未做）。

## 2. 实战缺口清单（按现场痛感排序）

### P0（高频、低成本或高价值，建议下一批先清）

> **状态更新（同日批次 11）：三项已全部落地**（NTLM 解禁 + skippedPoints 进 md/HTML/SARIF +
> PoC 复核预期，26 条新单测，见纪要 §十四与 CHANGELOG 第六批）。

1. **NTLM CLI 解禁**（成本≈0.5 天）：引擎三步握手完整（ntlmAuth.js/ntlmHandshake.js），
   只有 args.js:555 的陈日报错挡路。内网 IIS+Windows 认证是渗透高频场景，
   现在引擎能打、用户进不去。放开 parseAuth + REST auth.ntlm 子字段 + 两条测试。
2. **skippedPoints 进交付格式**（成本≈0.5 天）：md/HTML 的「结论可信度」节旁加
   「跳过 N 点（原因分布）」；SARIF 进 properties。这是「报告自证测全」的最后一公里，
   甲方验收最常追问的一句。
3. **响应侧取证进 PoC**（成本≈1 天）：布尔/时间通道的 PoC 附真假响应对
   （状态码 + 关键差异片段 + 耗时），复核人不用重放就能判读。
   证据链现在只有请求侧 + 检测器 trace（仅 JSON）。

### P1（明确价值、中等成本）

4. **headless 爬取（opt-in `crawlBrowser`）**：Playwright 已在 devDeps、e2e 已跑通
   浏览器通道（fullchain-lab），把它搬进引擎做 opt-in 爬取模式（渲染后收集 XHR/fetch
   端点 + 表单）。SPA 目标是当前最大整类盲区；成本大但一劳永逸。
5. **OOB 两处修**（成本≈0.5 天）：MySQL UNC 向量把 `host:port` 塞进 UNC 主机名
   （payloads/index.js:99-133），真实 Windows 解析不了 → 改纯 host 走 DNS 通道；
   SMB 命中只有触发向量没有接收端，文档明示「需配 DNS 域名」或加独立 SMB 监听。
6. **登录编排最小版**（成本≈2-3 天）：`--login-url`+凭据 → 自动 POST 登录 → jar 承接
   会话 → 会话失效自动重登（复用 scanValidityGuard 的失效信号）。
   全自动 SAML/验证码不做（诚实边界），覆盖「标准表单登录」这一最大子集。
7. **UDF 二进制分发**：对齐 sqlmap data/udf（内置编译好的 sys_eval so/dll，按位数选择），
   消除「全链就绪但需要现场自备二进制」的断点。
8. **inline Q 利用半 + Oracle fileWrite**：InlineQueryDetector.js:4-9 自述只实现检测半；
   Oracle 文件写 capabilities.js:43 明示未实现。两个都是 sqlmap 有而本仓无的利用面。

### P2（方向性投入，排期决定）

9. **NoSQL 深化**：当前仅 MongoDB operator 单形态、只检测不利用
   （NoSqlInjectionDetector.js:128-130），距 nosqlmap 差一个量级；SSTI 无绕过变体。
10. **GraphQL 独立通道**：现只有 4 类只读探测（payloads/index.js:549-556）+ Postman
    graphql body 归一化；可做 introspection 驱动的字段级注入点展开。
11. **变更差异扫描**：对比台账中同目标两次扫描，圈出新增端点/参数只测增量——
    重测场景的省时利器（台账/续扫地基已备）。
12. **`/api/metrics` Prometheus**（09-30 审计 P1 遗留）：扫描数/请求速率/队列深度。

### 与反向清单的对齐自检

本清单不触碰 09-30 审计 §9 五条反向项（不重写引擎语言、不动 REST API 形态、
不硬推覆盖率、不补 JSDoc、不追新框架）；headless 爬取与 GraphQL 通道是**面向目标**的
能力扩展，与「不引入 GraphQL」指的「自身 API 换形态」是两回事。

## 3. 现场一条龙建议（给使用者的落地口径）

```bash
# ① 授权红线永远第一条
--scope "api.target.example.com,10.0.0.0/8"
# ② 目标接入：Burp 抓包 → XML 导出 → 批量（多请求集合别用 -r，只取第 1 条）
-m burp_export.xml --scope ... --level 2 --cookie "SID=..." 
# ③ SPA 目标：浏览器抓包导 HAR/Postman 走集合入口（爬虫帮不上）
# ④ 检测：WAF 目标开 --identify-waf 让验链+变异搜索接管；强动态页给 --match-code/--regexp 锚点
# ⑤ 确认注入后再谈利用：EXPLOIT_ENABLED=1 + --authorized + 显式 scope + 写类加 --confirm-destructive
# ⑥ 交付前两件事：--poc-redact-auth（PoC 默认带真实会话凭据，忘开会自我泄露）；
#    补一段「跳过统计」人工说明（导出格式暂不含 skippedPoints，见 P0-2）
```

## 4. 结论

从实战看，这条工具链的「检测-利用-报告」主干已经能扛起真实交付：六库端到端、
PoC 逐 payload 可重放、护栏比 sqlmap 严格、WAF 闭环是差异化长板。
当前的四颗最扎手的钉子按序是：**SPA 接不进（需 headless，P1-4）、登录编排缺失
（P1-6）、交付格式缺跳过统计（P0-2）、NTLM 白卡在陈日报错（P0-1）**。
前三颗决定「能不能接更多真实目标」，最后一颗是半小时级的白捡能力。
建议下一批以 P0 三项开路（合计 ≈2 天，全是小刀快跑），P1 按现场需求排期。
