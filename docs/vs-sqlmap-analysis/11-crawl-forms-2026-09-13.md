# 11-crawl-forms-2026-09-13.md — 爬虫/表单自动发现与 level 解耦（对标 sqlmap --crawl/--forms）

> 复盘：此前误查为「crawlForms/crawlDepth 是死参数」——**结论错误**（grep 被 -First 截断），
> 功能早已实现且有测试（crawler.test.js / targetParser.crawl.test.js / targetParser.forms.test.js）。
> 本轮修正的是真实缺陷：**level≥5 门槛导致显式开启的功能对前端用户静默失效**。

## 一、问题确认（证据链）

- 前端 `src/shared/constants.ts`：默认 `crawlDepth: 1`（产品意图=自动发现同层参数入口），且
  ScanConfigPanel 有 Switch+Slider 暴露开关；
- 服务端 `config/defaults.js`：默认 `level: 1`、`crawlDepth: 0`（前后端默认不一致）；
- 服务端 TargetParser 门槛：`level >= 5 && config.crawlForms` / `level >= 5 && crawlDepth > 0`；
- 推算与实锤：前端默认档 = level 1 + crawlDepth 1 → `level>=5` 恒不满足 → **爬虫对全部前端
  用户（未改 level 的人）100% 静默不生效**。用户看到 UI「爬虫：开」实际一次都没爬。

## 二、修复（与 sqlmap 语义对齐）

- **移除 level 门槛，保留双重 opt-in**（`crawlForms` 默认 false / `crawlDepth` 默认 0）：
  功能默认仍关闭，显式开启即生效——与 sqlmap `--crawl=<depth>` / `--forms` 独立于
  `--level` 的语义一致。
- 风险钳制：双重 opt-in 已足够保守（服务端默认不开）；开启后的爬取量受 LinkCrawler 上限约束
  （每深度 ≤20 页、总量 ≤50 页、深度 1-3、同域、去重）。

## 三、改动清单

- `server/src/engine/TargetParser.js`：两处门槛 `level>=5 &&` → 仅 opt-in 开关；同步注释。
- `server/tests/targetParser.crawl.test.js` / `targetParser.forms.test.js`：原测试 `level: 5`
  改为 `level: 1`（把「低 level 开启即生效」锁进既有用例）；各加 1 条显式回归用例
  （「level=1 前端默认档 + 开启 → 必须产出点」），防止未来回归为「开了却不爬」。

## 四、验证

- 相关测试 55/55 全绿（+2 新用例）；服务端全量；e2e 检测回归（见结果）。
- 行为影响（预期）：前端默认档扫描会真正爬 1 层 → 注入点数略增（自动发现），部分场景检出
  提升；扫描时长受爬取量上限约束。API/CLI 未显式开启的用户行为不变（service 默认 crawlDepth=0）。

## 五、剩余差距（对标 sqlmap）

- sqlmap `--crawl` 还会解析 robots.txt / sitemap 种子，并支持 `--crawl-exclude` 正则排除；
  本工具种子=目标 URL + 发现链接中的 <a/form/script/link/iframe>（已包含）。
- sqlmap `--forms` 对 JS 动态表单（ajax/form 由 JS 生成）无解（同本工具）；本工具的
  CSRF token 提取与 POST 字段点生成已对齐甚至更细（isStore 存储点分类）。
- 建议后续：爬取 URL 数上限进入报告 summary（本次爬了几页/发现几个新点），提升交付透明度。
