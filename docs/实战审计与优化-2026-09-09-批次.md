## 一、这一批的主线：从「会不会漏检」转到「我们对目标做了什么」

上一批把「扫不出来 ≠ 没有漏洞」这条线接上了（可信度守卫 + scope + PoC 证据链）。这一批继续挖同一族问题，
发现真正危险的三件事都在**发包出口层与能力开关的语义**上：

1. **出口选项被手抄了四份**，每份漏的键不一样。`Detector.send` / `Detector.sendHead` / `sendInjection` /
   `Extractor._send` 各写一遍「config → httpClient.request(opts)」。后果不是崩溃，是静默的结论污染与
   失控的请求量：`--delay` / `--reqrate` / `--max-requests` 在**请求量最大的盲注提取阶段（第四份副本）根本没接**——
   用户以为已经限速、已经设了请求上限，实际只有检测阶段受约束。
2. **「没拿到响应」与「拿到空页面」同形**。`httpClient` 失败会抛 `AppError`，但 `sendInjection` 把它
   `catch { return null }`，而 60+ 处调用方写的是 `String(res?.data ?? '')`。于是连接被拒 / 超时 / 证书失败 /
   响应超限，在布尔盲注眼里是「真假两侧无差异 → 不可注入」，在时间盲注眼里是「无延迟」，在指纹阶段是
   「耗时超阈值 → 定库成功」。最后一条尤其讽刺：**失败会造出一个假的数据库指纹**。
3. **风险开关的语义是反的**。`--risk 3` 在 CLI 上会**无确认地把写文件/RCE/DoS 向量合进进程级 PAYLOADS**；
   在 REST/UI 上则**一条都不投**（扁平路径没有调用点）。同一个数字，一边是「没确认就开火」，一边是
   「以为开了火其实没测」。而 `BENCHMARK({SLEEP}0000000,MD5(1))` 是字符串拼接：`--time-sec 60` →
   六千万次 MD5，把客户共享库 CPU 打满几分钟——这是我们对目标造成的可用性问题，不是检测能力问题。

## 四、下一批清单（已核实、未实现）

### P0
1. **Exploiter「0 行」被写成已确认**：`ok:true, rows:[]` 与「空表」不可区分，`scanRunner` 回填 `report.data` 也不看行数。修法：空结果时追加一次恒真对照（`WHERE 1=1`），对照仍空 → `confidence:'low'` + note；对照非空 → 判「提取通路不稳定」。只在空结果时多一次请求。
2. **tamper 幂等声明不实**：`core/tamper/plugins/blindbinary.js` 声明 `idempotent:true` 但 `f(f(x)) !== f(x)`（链式或「被 WAF 拦后重跑」时数据损坏）；另有若干插件同类。修法：逐个跑双应用断言，不成立就改 `idempotent:false` 或加 marker 包裹。
3. **`--invalid` / `--invalid-logical` / `--invalid-bignum` 缺失**（`server/bin/cli.js` 参数表）：这组是缓存页/静态页噪声规避，是布尔盲注在真实站点上最常见的失败原因，优先级高于再加 200 条 payload。
4. **没有「已知注入点直接利用」入口**（也无 `--gpage`）：手工找到点后仍必须把 payload 塞回参数值并先跑一轮检测。修法：`config.knownPoint = {param, quote, paren, technique}` 跳过发现与指纹。

### P1
5. MySQL 报错族偏窄（缺 `floor(rand(0)*2)` group-by 重复键、`GTID_SUBSET`），且 `AND EXP(~0)` 被归 error 族却写成 `13=1` 恒真 → 不闭合上下文里制造假阳。
6. `extractionMaps` 零集合运算、零 `COLLATE` 模板：`Illegal mix of collations` 是 UNION 第一高频报错，没模板等于放弃这批点。
7. `union_extract` fixture 阈值余量仅 3 请求（max 120 / 实测 117）且 `nullSequence` 用 `Math.random()` → 该场景易 flaky。
8. MSSQL 拖库中文 HEX 往返不一致（`Exploiter.js` 两处编码路径不同）→ 报告里出现不存在的字符差异，客户对着原库核会反过来质疑结论。
9. undici 通道不支持 SOCKS5（本批已补齐解压，代理侧仍是显式拒发）：接 `undici` + socks dispatcher，或在文档里写死「H2 与 SOCKS 互斥」。
10. `report.summary.skippedPoints` 汇总比例仍缺（只有点级 `skipReason`）；`decideBlockPolicy` 的退避不会动态降 `ratePerSec`（只退一个点边界）。
11. OOB 不可用建议在 `report.summary.oobUnavailable` 标注（现状只 warn）。
12. 统一响应包把业务错误也返回 **HTTP 200 + code**：监控/网关/代理看不到失败率，`curl` 脚本 `set -e` 也拦不住。前端已依赖该形态，改动需分两步（先发 `X-Error-Code` 头 + 保留 200，再灰度切状态码）。

### P2
13. `e2e/waf-real/` 是一套可用的 OWASP CRS v4.1 静态规则引擎（`crs-engine.js` + `crs/*.conf`），目前**未跟踪**。要么入库当回归资产，要么明确废弃；现在这样是「能力躺在工作区里没人知道」。
14. 面板仍有若干键未进 `SCAN_CONFIG_KEYS`（`delay`/`reqRate`/`maxReq`/`productionMode`/`confirmDestructive`/`http2`…）：契约测试已能兜住「登记了却没接线」，但「引擎支持、面板没有入口」需要产品决策后逐个补 UI。

## 五、待拍板（上一批提出，仍无答复）
