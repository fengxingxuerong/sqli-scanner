## 三、缺陷清单（按发现顺序）

### 1. redteam-lab 编排缺陷（run-all 假 PASS）——最典型
- 现象：run-all 报 redteam-lab 通过（41.8s），但提示行是 r2 done: 0/26 hit——19 个注入点全部漏检。
- 根因：run-scan.mjs 只负责扫描，不含起靶场逻辑（需要 env.mjs 常驻拉起 MySQL+PG+靶场）。run-all 直接把 run-scan 当入口，靶场没起 → 全部连接失败；而 run-scan 依然 exit 0，run-all 只看退出码 → 假 PASS。这正是 acceptance.mjs 注释里说的「中间层自报成功、无人校验外部事实」。
- 修：新增 e2e/redteam-lab/run-with-env.mjs 编排包装：先常驻拉起 env.mjs → 靶场端口就绪作为硬前置（90s 超时即失败）→ 运行 run-scan → finally 杀 env。run-all 的 redteam-lab entry 指向 wrapper。
- 修复后：19/19 漏洞点命中 + 7 安全对照 0 误报。

### 2. Exploiter.myOsShell 误诊「UDF 未注册」（真机实测）
- 现象：udf-lab step6 osShell("whoami") 返回 ok:false + "UDF 未注册，建议调用 udfInstall 后重试"，但同一注入点直调 extractScalar("SELECT sys_eval(""cmd /c echo X"")") 能拿到回显——UDF 明明已注册。
- 根因：中文 Windows 的 whoami 输出含 GBK 原始字节；CAST(... AS CHAR) 无法字符化 → 整个标记表达式得 NULL → 回显列是字符串 NULL 而非 __S__..__E__ → 路径1 判空 → 直接跳到路径3「未注册」结论。把「输出不可字符化」误诊为「未注册」，会把调用方引向重投 DLL 的错误处置方向。
- 修：Exploiter.js myOsShell 新增路径 2.5——用确定 ASCII 输出的 cmd /c echo <随机数> 探测：echo 命中 → 返回专用诊断（已注册、命令已执行、输出不可字符化、suggestHexEcho: true 指引 hex 编码回显）；echo 也不命中 → 才是真正未注册。
- e2e 同步：step6 命令从 whoami 换成 cmd /c echo osshell_ok（whoami 的 GBK 输出不可字符化是环境事实不是引擎缺陷），step6 现在验证的是 osShell 真实 ok 路径。

### 3. recall-lab mock 求值器未跟进引擎 WRAP 升级
- 现象：detection-runner 的 union_extract / extract_mock_values 2 FAIL——databases/tables 提取全空。
- 根因：引擎 2026-09-12 的 WRAP 修复（commit 07a1851）把 MySQL 家族标记包裹升级为 CONVERT(CONCAT(...) USING utf8mb4) COLLATE utf8mb4_bin（修 UNION 混 collation 报错），但 recall-lab 的 SQL 求值器不识别 CONVERT(... USING ...) 与 COLLATE 尾巴 → 求值落 unknown → 回显问号 → 提取判空。引擎与靶场演进不同步的典型。
- 修：lab-server.js evalItem 加两个分支：convert（剥 USING cs / 类型参数后对主表达式求值）+ 顶层 collate 尾巴剥离（排序规则声明不改变标量值）。
- 修复后：19/19 PASS / 0 FAIL / 0 WARN（连之前 3 个 WARN 的请求数超限都归零——提取不再浪费探测请求）。

### 4. real-mysql-lab 端口漂移（F4 修复漏网）
- 现象：0.6s 失败，ECONNREFUSED 127.0.0.1:3307。
- 根因：2026-09-10 F4 已把 init-db/lab-app/verify 的默认端口 3307→3306，但 verify.mjs L25 漏改。
- 修：统一 3306。修复后 10/10 PASS（noisy 首跑 10.3s 只出 time、二跑起 5.8s 稳定出 boolean——冷缓存噪声自适应首轮偏慢，属预期非回归）。

### 5. udf-lab DLL 投递 EBUSY（环境残留，非代码缺陷）
- 现象：copyfile udf_sys.dll → plugin_dir 报 EBUSY。
- 根因：上一轮测试残留的 udf 函数已注册，mysqld 进程加载了 DLL 文件句柄锁死。
- 处置：DROP FUNCTION → 重启 mysqld 释放句柄 → 清理残留 DLL → 复跑即 PASS。此问题对新人复现是隐形坑。

## 过程中发现的环境级问题（非代码缺陷，复现须知）

1. **mysqld 存活周期**：redteam-lab 的 env.mjs 退出时会连带杀掉它拉起的 mysqld —— 长跑 run-all 时后面依赖 MySQL 的靶场（real-mysql-lab / udf-lab）会 Access denied。对策：先独立拉起 mysqld 再跑 run-all（env.mjs 探测到已监听即复用）。
2. **端口串扰**：常驻调试用靶场进程会占住 8150/8231/8140 等端口，verify 脚本若不校验 listen 会静默扫错目标（pentest-lab 已修复守卫，其余脚本建议同样处理）。
3. **凭据环境变量**：多个靶场脚本读 `MYSQL_PASSWORD ?? 'root'` / `LAB_DB_PASSWORD ?? ''`，运行前显式设置两个变量可避免歧义。

## ratePerSec=10 对 e2e 时长的影响

显式 0 值现在真正表示不限速（修复前实际是 defaults），本地靶场套件速度不受影响；
真实受限路径（未显式传 ratePerSec 的 CLI/REST 调用）耗时约变为原来的 2-5 倍 —— 这是
保守化默认值的预期代价，追求速度的场景应显式调高（前端滑条 / CLI --rate）。
