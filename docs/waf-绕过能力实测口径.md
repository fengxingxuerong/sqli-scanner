**执行器保真度门禁（`crs-fidelity`，用 CRS 官方回归集把执行器自身钉住）**：**族 942 99.6% / 族 930 100.0%，两族各 0 未点名分歧 → PASS**（基线按族各一份文件）。

该套件在 2026-09-19 23:15 曾是**唯一 FAIL**（96% / 23 条未点名分歧），当日定位并修复：

| 根因 | 说明 |
|---|---|
| CRS pattern 用 PCRE 的 `(?i:…)` 组级大小写开关 | 本仓跑在 **Node 22.22.2 / V8 12.4**，该语法（ES2025 regex modifiers，需 V8 13 / Node 23+）直接抛 `Invalid group` |
| 执行器 catch 后返回 null | 命中失败的 5 条规则（942160 / 942220 / 942250 / 942361 / 942450）**恒不命中** → 官方回归集漏 23 条 |

修复 = `toJsRegex()` 统一把 `(?i)` 删掉、`(?i:…)` 降级为 `(?:…)`（本执行器恒以 `flags:'i'` 编译，二者等价），
装载期普查探针与运行期 `execOp` **共用同一函数**，避免两套真相。缺陷注入复验：还原为不降级 →
保真度跌到 13.2% / 600 条未点名 → 门禁 FAIL（不是崩，是红）。

**自动路径（不显式配 tamper）**（`npm run waf-auto`）：
引擎自行识别拦截证据 → 链验证选中 `['dash2hash','hexliterals']`（日志 `WAF 链验证：[dash2hash,hexliterals] 探针放行`）
→ 重跑补全。三项关键使能修复：

1. **重跑前重探闭合前缀**：主轮 boundary 探测的 payload 不带 tamper，CRS 下被 942460 拦光 →
   回退空串 → 重跑探针无引号闭合（`alice AND 1=1#` 落进字符串字面量）→ 真假双双空结果 → 门控失败。
   重跑已带 tamper，重探即得正确 `'`（实测 `重探闭合前缀："" → "'"`）。
2. **重跑候选纳入「已命中但快速层技术位不全」的点**：主轮只中 boolean 的点原本被判「已命中」而排除，
   union 面永远补不上。
3. **链验证只认硬拦截**：原判据含「响应体缩水 50% = 软拦截」，而 payload 生效后结果集本就变空/变短
   （如恒空页的 `/blind`）→ 每条链都被误判失败 → 重跑整轮跳过。
