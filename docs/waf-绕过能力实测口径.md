该套件在 2026-09-19 23:15 曾是**唯一 FAIL**（96% / 23 条未点名分歧），当日定位并修复：

| 根因 | 说明 |
|---|---|
| CRS pattern 用 PCRE 的 `(?i:…)` 组级大小写开关 | 本仓跑在 **Node 22.22.2 / V8 12.4**，该语法（ES2025 regex modifiers，需 V8 13 / Node 23+）直接抛 `Invalid group` |

修复 = `toJsRegex()` 统一把 `(?i)` 删掉、`(?i:…)` 降级为 `(?:…)`（本执行器恒以 `flags:'i'` 编译，二者等价），
装载期普查探针与运行期 `execOp` **共用同一函数**，避免两套真相。缺陷注入复验：还原为不降级 →

**自动路径（不显式配 tamper）**（`npm run waf-auto`）：
引擎自行识别拦截证据 → 链验证选中 `['dash2hash','hexliterals']`（日志 `WAF 链验证：[dash2hash,hexliterals] 探针放行`）

3. **链验证只认硬拦截**：原判据含「响应体缩水 50% = 软拦截」，而 payload 生效后结果集本就变空/变短

## 真机口径现行版（2026-09-28 起，截至 2026-10-14）

> 本节是**真 ModSecurity 对拍的现行结论**；上表（PL1/PL2/PL3/PL4）仍是自实现执行器口径，
> 两者**档位不同、不可互证**（自实现 ≈ PL3 档，真机跑 PL1/PL3 双档）。本节数字全部有 CI run /
> 落盘报告可复核，引用时连同轮次与分母一起引。

**判定口径（自 09-28 起收紧，之后未变）**：

1. **打穿 ≠ 放行**：同一条样本必须同时满足「过了 WAF」且「MySQL 真的执行并吐出证据」
   （结果集标记 / 报错短语），回显不算。
2. **真分母是直连上界**：同批样本不经 WAF 真正取到数据的条数（`MODSEC_MIN_UPPER=4` 闸门，
   不够就红、不静默出数）。绕过率的分母看上界，不看 19。
3. 镜像 tag 未钉死 ⇒ **CRS 版本逐轮记录**（09-28 起 4.29.0，D14 起 4.30.0）；
   跨轮比较前先确认同镜像 digest（D14 的 A/B 对照即取同日晨 nightly 的同 digest）。
