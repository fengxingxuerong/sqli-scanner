## 3. 历史实测取证归档（原文件注释，不删教训）

以下结论是既有真引擎/官方文档证据，迁移后**行为逐字符保持不变**，不得以「统一风格」
为由顺手改动：

- **HSQLDB / MonetDB 标识符**：HSQLDB（`jdbc:hsqldb:mem:`，非 MySQL 兼容模式）真引擎
  实测反引号语法错、双引号可用；MonetDB 官方手册《Lexical Structure》只定义双引号
  标识符。原 `escCols` 把它们归反引号组是错的，2026-09-22 修正为双引号。
  ⚠️ MonetDB 本机无真引擎，该项仅基于官方文档 + 静态自洽性，**未经真机执行验证**。
- **Derby**：`CAST(x AS VARCHAR)` 无长度被拒；`IFNULL(CAST(int AS VARCHAR))` 报
  `Cannot convert types 'INTEGER' to 'VARCHAR'；`COALESCE(CAST(x AS VARCHAR(4000)),'')`
  真引擎实测通过。故 `nnExpr` 与 `nullSafeQuoteCol` 都用 COALESCE + 显式长度。
- **H2**：`IFNULL(CAST(x AS VARCHAR),'')` 实测可用，与 Derby 分支特意保留差异。
- **MySQL 家族 WRAP**：`CONVERT(... USING utf8mb4) COLLATE utf8mb4_bin` 是为修
  `Illegal mix of collations for operation 'UNION'`（mixcols 靶点实测：三通道命中但拖库 0 行）。
- **SQL Server / SQLite 的历史契约**：`escCols` 与 `quoteCol` 的引号策略故意不同
  （MSSQL：escCols `[]` / quoteCol `"`；SQLite：escCols `"` / quoteCol `` ` ``），
  两组写法在各自引擎都合法，既有测试已锁定。迁移时**未统一**。
- **ClickHouse / Firebird**：`concat` / `||` 遇 NULL 整串变 NULL，聚合时整行丢失，
  必须显式 `ifNull(toString(...),'')` / `COALESCE(CAST(...),'')`。
- **SQL Server / Sybase 无 `wrapNoCast`**：`+` 遇 int 直接报错（需 CONVERT），
  `--no-cast` 对这两库不降级正确性；数据里故意不写该字段，调用方回退 `WRAP`。
- **DM8 归一化**：`resolveDbms('DM8') → 'Oracle'`，故 `nullSafeQuoteCol` 实际取
  Oracle 条目；`nnExpr` 用的是未归一化的原始 `dialect`，取 DM8 条目 —— 两者表达式
  恰好相同（NVL + VARCHAR2(4000)），数据里两处都写了同一值以防将来分叉。

## 5. 诚实边界

- **等价性证据是既有单测，不是新旧实现互比**（后者两边都是本批次写的，属自证）。
  本批次**未跑真靶场 e2e**，因为方言层迁移的等价性由 846 行单测覆盖；
  若后续要声称「检出率不变」，仍需真靶场复验。
- `WRAP` / `WRAP_NOCAST` / `INLINE_CONCAT` / `HIGH_FREQ_DBMS` / 别名正则 /
  `HASH_COMMENT_RE` 是**模块加载期**从数据派生的常量：运行时往内存对象加方言不会
  让它们即时变化，改磁盘 JSON 后重启进程才生效。这仍是「不改代码」，但不要误读成
  「热加载」。
- **9 种「仅模板」DBMS 的能力等级不变**（TiDB/DM8/ClickHouse/DB2/Sybase/Firebird/
  Informix/Access/MonetDB 等），本批次只是把已有知识换了个容器，
  **没有新增任何真引擎验证**，不构成能力提升声明。
- 新增 JSON 已纳入 `arch-guard` 的 `server/src` 体积判据（与 E5-2 的 `registry.json`
  同一纪律：数据搬进 JSON 不等于把体积债藏进盲区）。
