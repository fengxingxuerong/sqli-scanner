## 一、一句话结论

**这是一个"工程纪律远超产品完成度"的工具**：它的可信度建设（门禁自证、靶场真值、缺陷注入复验、口径单一来源）
已经做到商业工具罕见的水平，实测检出成绩在同题对照里不虚 sqlmap；但它**现在处于"CI 全红、工作区在制品未收口"的状态**，
且对外宣言的边界（真实 WAF、9 种方言、桌面版）仍有大块空白。**能当实战辅助工具用，还不能当对外交付的成品发布。**

## 五、优点（按含金量排序）

### 1. 门禁的可信度建设 —— 全项目最硬的资产

不是"跑通了测试"，而是**反复拷问"这个门禁真能看见它声称在管的东西吗"**，并留下可复核的疤痕：

| 发现过的门禁谎言 | 处置 |
|---|---|
| CI 两个 job 引用**不存在的文件** + `continue-on-error` → 从未拦过人 | 新增 `refs:check`，含"自指注入"复验 |
| `facts:check` 只比 README↔json，**从不校验 json 是否当前代码采的** | 加测试文件 sha256 指纹；基准过期时**拒绝** `--fix` |
| 验收报告被定向跑覆盖 → 全量结论丢失 | 头部加版本凭证 + `N/M 跑出断言`，非全量写 `.partial.md` |
| `ci-local` 声称对齐 ci.yml，实少跑 3 个 job | 每个 job 必须"被覆盖"或"显式登记排除"，未登记启动即 exit 2 |
| `pentest-lab/verify.mjs` 无条件 `exit(0)`，FAIL 标签纯装饰 | 改为按失败行 exit 1 |
| 靶场 5 份真值清单**无任何一致性判据** | 新增 `targets:check`，双向守卫（缺登记红 + 清单腐烂也红） |
| 沙箱起不来被记成产品 FAIL | 抽三态判据 `suiteVerdict.mjs`（PASS/SKIP/BLOCKED/FAIL）+ 12 例含 4 反例 |

**这类缺陷的正确率极高**：几乎每一条都是"结论看着正常、语义完全不同"的同一病根换器官。
大多数团队一辈子不会发现其中任何一条。

### 2. 诚实作为工程约束，而不是道德表态

- 报告里带 `reliability` / `validity.status="unreachable"` / `dbmsEvidence.caveat` / `constraints`，
  **目标不可达时拒绝输出"未检出"**（`scanValidityGuard`，真靶场级验证过）
- README 明写"⛔ 模板适配 9 种，请当**待复核线索**而非证据"
- TODO 里主动写 **§E「本轮未跑的门禁（诚实记录）」**、**§P 口径更正**、**「如实留白，不再编因果」**
- 甚至更正自己的提交标题口径：Derby 其实被顺带修好了，但标题只提 HSQLDB → 长期口径失真，**主动留档为教训**

### 3. 覆盖广度是真的，不是列表堆砌

9 通道 × 18 方言 × 6 注入面 × 1470 payload × 228 tamper × 62 WAF 指纹 × 6 报告格式 ——
且**每类都有靶场**（multipart 有 `/mp` 靶点、NTLM 有 mock 服务端 10 项断言、UDF 有隔离沙箱 5+7 项）。

### 4. 失败模式分类比同类工具精细

- `wrote:true / verified:false` 分开（旧实现把"请求发出去了"报成"写入成功"）
- `probeInconclusive` / `boundarySkipReason` / `blindLenCapped` —— 每个"没结果"都能回答"为什么"
- "顶到上界"分三档裁决（合法长值 / 用户授权截断 / 判据失效）

### 5. 性能优化有量化手法，不靠直觉

用记录型 stub 在**无网络/无服务/无 DB** 下精确计数请求数 —— 突破了"性能结论要靶场"的死结。
并且**推翻了自己的推断**：原以为"跨检测器重复请求 10–15 次"，实测**只有 1 种 × 5 份 = 3.4%**，
"错了一个数量级"；真正的大头是 union+error。**先量化再讨论**这条已经内化成纪律。

## 七、进步空间（按性价比排序）

### 立刻（今天就能做，不依赖 CI）

1. **收口在制品**：payload 声明式迁移这批 → 单测 → `git add` → `facts:refresh` → `facts:fix`（一批只 refresh 一次）→ 提交。
   ⚠️ `facts:refresh` 会实跑 `test:server`（spawn Express），按本地铁律**先问一句**。
2. **修 README:136 那行口径**（4/11 → 6/9），顺手在 `facts:check` 里加一条"方言分层三数之和 = 18"的一致性规则 ——
   这类"同一口径两处漂移"正是本仓最擅长的守卫题材。
3. **确认 Actions 账单**：提额度或换私有 runner。**这是解开一切验收阻塞的钥匙。**

### 高价值（需外部条件）

| **性能：`pickErrorTemplates` 整包返回** | 最大候选优化点（error 通道 62 条 ≈ MySQL 全模板，与注释称的"≤8"不符）。**但省多少必须靶场验检出率** | `perf:budget` 前后对照 + 红队/blackbox 检出率不降 |

### 中长线

- **方言体检制度化**：H2/HSQLDB/Derby 那套"真引擎 + 机械不变量断言"已可复制（`ENGINE_JARS` 取证脚本 + 逐函数查官方语法）→
  按风险排 9 种模板方言，**一次一个，每次留下产物与版本凭证**。切忌跨库类推（同 SQL 合法性可能相反）。
- **前端 `func` 覆盖率的结构性澄清**：实测 86 个未覆盖函数里 69 个是 JSX 内联事件、真逻辑只剩 13 个 →
  **数学上到不了 85%**。出路不是"测样板"，而是**把指标改为"真逻辑覆盖率"**（可解释、可提升、不误导）。
- **桌面版补验收**：安装 → 启动 → `ENGINE_TOKEN` 握手 → 一次真实扫描 → 报告落盘，五步一条 e2e。
- **同题对标定版**：与 sqlmap 约定同一批靶点、同一档位、双方各跑 3 次取中位，出一份可被第三方复现的对照报告。
