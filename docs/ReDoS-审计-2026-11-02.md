# ReDoS 审计 —— 检测器正则的灾难性回溯面（D232）

> 2026-11-02 · 判据脚本 `scripts/redos-audit.mjs`（`npm run` 可直接跑，已接入 `gate:close`）
> 产物 `docs/redos-audit-2026-11-02.json`（静态候选 + 逐条探测耗时，可复核）

## 结论

**扫描 446 个文件 / 提取 1047 条正则；静态候选 12 条，动态探测全部 <1ms —— 未发现可利用的灾难性回溯。**

其中 1 条（`errorSig.js` 的 45 分支大交替）在 10MB 响应体上确实要 35ms/次，但那是**线性**扫描，
不是回溯爆炸，已由 D230 定量并判定为「不漏检的必要代价」。

## 为什么这条值得做（不是性能，是 DoS 面）

检测器的正则**跑在目标可控的响应体上**（上限 10MB）。目标只要回一段精心构造的 HTML，
就能让扫描器在单条正则上卡死 —— 攻击者不需要打穿任何东西，只要让扫描器别动。
《卡死风险报告》P2-4 指出这项审计一直没做，本批补齐。

## 方法（静态排序 + 动态定论）

| 阶段 | 做法 | 为什么不能只用一种 |
|---|---|---|
| 静态 | espree 解析 AST，精确取正则字面量与 `new RegExp('字面量')`，按「组内量词+组外量词 / 交替+量词 / 相邻重叠量词 / 双 `.*` 」打分 | 源码文本匹配会误抓注释与除法；但静态只是**排序**，不产生结论 |
| 动态 | 对候选喂病态串（`a`×N + 破坏后缀、`1`×N + `x`、空格×N + `#`，N ∈ {24,26,32}），在 **worker 线程**里跑，250ms 未返回即 `terminate` 并判危险 | 静态启发式必然误报（见下），结论以真实执行为准；worker 隔离保证「真挂住」时审计自身不陪葬 |

自证：`--selftest` 用 `(a+)+$` 与 `^[a-z]+$` 两个已知样本验证判据有区分度（危险必判出、安全不得误报、
静态打分危险 > 安全），已进收口清单。

## 12 条候选逐条判定

| # | 位置 | 正则 | 判定 |
|---|---|---|---|
| 1 | `core/tamper/plugins/if2case.js:43` | `/^\(+\|\)+$/g` | 启发式误判：`\(` 是**字面括号**不是分组，无嵌套 |
| 2 | `core/tamper/plugins/binary.js:45` | `/(\s+binary)+/g` | 形态上是嵌套量词，但内层每次必须消费固定串 `binary`，不会指数回溯 |
| 3 | `engine/parseErrors.js:20` | `/(?:near\|at)\s+["']((?:[^"']\|['"]){1,80})/i` | 有 `{1,80}` 上界，有限回溯窗口 |
| 4 | `engine/parseErrors.js:22` | `Incorrect\s+syntax…{1,80}` | 同上 |
| 5 | `engine/payloadRegistry.js:74` | `(?:^\|[\s'"(;])(?:drop\s+table\|…)` | 相邻量词误判：交替分支全是固定词 |
| 6 | `engine/payloads/index.js:230` | `/PostgreSQL\s+\d+/i` | 单量词，线性 |
| 7 | `engine/payloads/index.js:233` | `/(Oracle\|Release\s+\d+\.\d+)/i` | 交替分支首字符不同，无共享前缀 |
| 8 | `core/dbDrivers.js:396` | `/\s+ORDER\s+BY\s+\d+.*$/is` | 单 `.*` 且有 `$`，线性 |
| 9 | `core/digestAuth.js:37` | `([a-zA-Z][a-zA-Z0-9_-]*)\s*=\s*(?:"((?:[^"\\]\|\\.)*)"\|([^\s,]+))/g` | 经典 quoted-string：`[^"\\]` 与 `\\.` **互斥**，每字符只有一条路 |
| 10 | `core/tamper/plugins/scalarselectinline.js:40` | `'(?:[^'\\]\|\\.)*'\|"…"\|`…`` | 同上 |
| 11 | `engine/payloads/index.js:229` | `/^\d+\.\d+\.\d+(?!(?:.*MariaDB\|.*TiDB))…/i` | 有 `^` 与 `$` 锚点，窗口受行长度约束 |
| 12 | `core/errorSig.js:37` | 45 分支大交替 | 线性扫描（D230 实测 35ms/10MB），无回溯 |

## 诚实边界（这些没被证明）

1. 动态探测只用了 **3 种通用病态串**。它能证明「这三类输入不爆炸」，**不能**证明「任意输入都安全」。
   需要特定前缀才能进入回溯区的正则（如 `near "` 开头）不在探测覆盖内 —— 对第 3/4 条这类，
   判定依据是 `{1,80}` 的**有限上界**（人工复核），不是动态结果。
2. 只提取**可静态求值**的正则。`new RegExp(变量)` 共 12 处，逐处核对后确认全部是模块内常量拼接
   （`KEYWORDS` / `KW` / `PH_PREFIX`），无用户输入进入 pattern。
3. `--param-exclude` 接受用户提供的正则串（clamp 200 字符），**未纳入本审计**：它作用于参数名
   （短串）而非响应体，且是用户给自己填的表达式 —— 风险面与「目标可控输入」不同类。
4. 判定阈值 250ms 是工程折中：低于它不判危险，意味着「5ms 级的中度回溯」不会报警。
   当前 12 条候选全部 <1ms，离阈值还有两个数量级。

## 接入

```bash
node scripts/redos-audit.mjs              # 收口门禁跑的形态（不落盘，1.4s）
node scripts/redos-audit.mjs --static     # 只看候选清单
node scripts/redos-audit.mjs --out=docs/redos-audit-2026-11-02.json
node scripts/redos-audit.mjs --selftest   # 判据自证
```

退出码：`0` 未发现 / `2` 确认存在灾难性回溯（CI 与 `gate:close` 按此判红）/ `1` 自证失败。
**默认不落盘**：这道门禁每次收口都跑，写文件会让工作区无故变脏（facts/refs 门禁会感知）。
