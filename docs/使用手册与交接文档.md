# sqli-scanner 使用手册与交接文档

> 版本：master @ 14c0f26（2026-09-16）· 形态：Node.js CLI（server/bin/cli.js）+ 可选 Web UI（server/index.js）
> 定位：授权安全测试用的 SQL 注入检测平台。单目标输入 → 自动多技术检测 → 全量 payload 证据 → 双格式报告 → 可追溯台账。

---

## 1. 环境搭建（从零到首扫）

### 1.1 依赖
| 依赖 | 版本 | 用途 |
|---|---|---|
| Node.js | ≥ 22 | 引擎与 CLI 运行时 |
| npm | 随 Node | 依赖安装 |
| MySQL 8.x（可选） | 8.0+ | 真机靶场 / fileRead 验证（root/root） |
| PostgreSQL（可选） | 16 | OOB 带外靶场 |
| SQL Server Express（可选） | 2022 | MSSQL 真机靶场（实例 SQLI，TCP 65039） |
| Oracle 26ai Free（可选） | 26ai | Oracle 真机靶场（1521/FREEPDB1） |

### 1.2 安装
```powershell
git clone <repo> && cd sqli-scanner/server
npm install            # 引擎依赖（mysql2/pg/mssql/oracledb 均为可选按需）
node bin/cli.js --help # 冒烟：打印帮助即安装成功
```

### 1.3 Docker 部署
```powershell
docker compose up -d          # Web UI + 引擎（非 root，默认绑 127.0.0.1:4567）
# 浏览器打开 http://127.0.0.1:4567
```

## 2. 快速开始（一条命令全流程）

```powershell
# 最小命令：单 URL → 自动参数发现 → 多技术检测 → HTML 报告 + 台账登记
node bin/cli.js -u "http://target/item?id=1" --format html -o "D:\reports\"

# 原始请求导入（Burp/ZAP 抓包，对标 sqlmap -r）
node bin\cli.js -r request.txt --format html -o reports\

# 爬虫 + 表单发现
node bin\cli.js -u "http://target/" --crawl 1 --forms -o reports\

# 拖库（数据提取）
node bin\cli.js -u "http://target/item?id=1" --dump -D sqli_lab -T users

# 台账检索
node bin\cli.js ledger list
node bin\cli.js ledger show <scanId>
```

输出目录结构：`report.html`（人读）+ `report.md`（交接）+ `report.json`（机读）。

## 3. 参数速查（高频）

| 参数 | 说明 |
|---|---|
| `-u <url>` | 目标 URL（含参数） |
| `-r <file>` | 原始 HTTP 请求文件（Burp 导出，支持 multipart/JSON body） |
| `--batch <file>` | 批量 URL 文件（每行一个） |
| `--format <f>` | json/html/csv/markdown/sarif |
| `-o <dir\|file>` | 报告输出（目录语义自动写 report.html+md 组） |
| `--level <1-5>` | 检测深度（3=默认全参数） |
| `--techniques <list>` | 限定技术（union,error,boolean,time,stacked,inline） |
| `--crawl <n>` / `--forms` | 站内爬取深度 / 表单发现 |
| `--csrf-url/--csrf-token` | CSRF 会话（对标 sqlmap） |
| `--skip <params>` | 排除指定参数 |
| `--tamper <list>` | WAF 绕过插件链（228 个） |
| `--rate <n>` | 限速（默认 10 req/s） |
| `--dump/-D/-T` | 拖库（库/表） |
| `--os-cmd` | os-shell（需 EXPLOIT_ENABLED=1 + --authorized） |
| `ledger list/show` | 台账检索 |

## 4. 报告结构（每份报告包含）

1. **执行摘要卡**：扫描ID、风险等级、库指纹、注入点/漏洞计数、起止时间
2. **漏洞表**：注入点/技术/DBMS/风险等级/CVSS/描述
3. **多维度分析**：注入类型 × 受影响参数 × 库指纹 × WAF 交战记录 × 可利用性
4. **PoC 复现区**：每漏洞按 payloads 逐条展开（PoC-N-M，主命中/补充 payload 分层），
   每条含 method/url/payload/curl 一行命令/原始 HTTP 报文（可 -r 直接导入复放）
5. **修复建议**：按漏洞逐条（CVSS 评分 + 处置建议）
6. **台账一致性**：report.json 与 data/ledger/<scanId>/report.json 同源可核对

## 5. 扫描台账

- 目录：`server/data/ledger/<scanId>/`（可用 `SQLI_LEDGER_DIR` 环境变量改）
- 内容：`meta.json`（时间/目标/注入点/payloadHits/verdict）+ `report.json/html/md` + `poc/*.txt`
- 全局索引：`data/ledger/index.jsonl`（追加式，一行一扫描）
- 检索：`cli.js ledger list [n]` / `cli.js ledger show <scanId>`

## 6. 安全基线（默认即合规）

- 启动即要求授权确认（--authorized / 交互确认），未授权目标强制拦截
- 默认限速 10 req/s、验证型无害 payload 优先
- 高危操作（os-shell/fileWrite/dump 全库）需 `EXPLOIT_ENABLED=1` 显式开启
- 阴性结论输出 `inconclusive` + 复扫建议，绝不谎报「安全」

## 7. 常见问题

**Q: 报告里 verdict=inconclusive 但有 vulns？**
A: inconclusive 表示存在被 WAF 压制或无法完全确认的场景；vulns 是已确认命中。两者不矛盾，
报告 WAF 交战章节会给出降速/加白名单复扫建议。

**Q: -o 写的是单文件还是目录？**
A: 目录语义：路径已存在为目录或以 `\`/`/` 结尾 → 写 report.html/report.md 组；否则单文件。

**Q: MySQL fileRead 返回空？**
A: MySQL 8 默认 `secure_file_priv=NULL` 禁用文件读写——数据库合规默认值，非工具缺陷。

**Q: target 是 SQL Server 但只扫出 template 级结论？**
A: SQL Server 已 verified（真机闭环）；若报 caveat 说明走了 template-only 档，
检查 --dbms 是否被显式覆盖。
