### 3.4 WAF 对抗

- **228 tamper**（sqlmap 官方全集）+ 算子替换族 + 拦截证据驱动的自适应重跑（≤2 轮）
- 62 家 WAF 指纹 + 推荐链
- 自研 SecRule 执行器（非 ModSecurity 引擎）：OWASP CRS v4.1.0 全规则 ≈PL3 最严档下 5/5 注入场景有检出、技术位合计 8，安全对照零误拦
- **真 ModSecurity 对拍（09-28，CI run #97）**：真库靶站（MySQL）上以「过 WAF 且 SQL 真执行吐出证据」为打穿判据——**放行 8 个插件、真正打穿 1 个**，CRS 4.29.0 PL1/PL3 双档对拍
- 已知边界：数值上下文 UNION 被 CRS 942361 按参数起始形状拦死（union 技术位仅字符串上下文可得）；真实云 WAF（安全狗/阿里云/Cloudflare）未实测

### 3.5 合规与安全设计（攻击工具自防御）

scope 授权逐跳硬约束（302 圈外拒发）· SSRF 分层 + DNS 钉死防 rebinding · 凭据全链路打码 · API token 恒时比较 · 非 root 容器 · ### 3.6 结构化 body 通道（现代 API 注入面）

| 通道 | 入参 | 注入点形态 | 状态 |
|---|---|---|---|
| JSON 嵌套 | `jsonBody`（对象） | 叶子点路径 `user.id` / `tags.0` | ✅ 2026-09-08 起，三端齐备 |
| XML / SOAP | `xmlBody`（字符串）/ CLI `--xml-body`·`--xml-body-file` | 叶子点路径 `soap:Envelope.soap:Body.GetUser.id` | ✅ 2026-10-01 起（对标 ghauri），真靶场 `/soap` 取证 |

- 两类都不把整份 body 当一个参数（那样 `String(v)` 之后就再也注入不进去）。
- XML 通道**只认「元素 + 文本」**：注释 / CDATA / DOCTYPE / 正文处理指令整体放弃（解析失败即 0 注入点，
  由 REST 侧 warn 播报，不发畸形报文 —— 畸形会让目标解析失败，整轮判「不可注入」，比诚实地说没发现更糟）。
  属性不做注入点（SOAP 参数都在元素文本里）。

### 3.7 目标认证（静态注入四条 + 登录编排一条，全已接线）

**静态注入**：Basic · **Digest**（挑战应答，按主机缓存挑战/nc）· **NTLM**（三步握手，自实现 DES 免 legacy provider）·
**mTLS 客户端证书**（`clientCert` PEM，对标 sqlmap `--cert`；与 `insecureTls` 正交）。

**登录编排**（`--login-url` + `--auth user:pass`，2026-10-02 新增）：标准 HTML 表单登录的
自动编排 —— GET 登录页自动探测字段（密码框定位 / 用户名框回溯 / hidden+CSRF 透传）→
POST 凭据 → CookieJar 承接会话 → 扫描遇 401/403/登录跳转时**自动重登一次并重试原请求**。
会话会过期的目标（token 一小时）此前扫到一半全变 401 ⇒ 后半程全判「不可注入」且报不出原因。

- 真靶场取证（`e2e/login-lab`，会话用 6 次即过期）：**14 次成功自动重登**、靶站
  200=79 / 401=125、`points=1` **`vulns=2`**；**对照组（不给 `--login-url`）0 检出**
  —— 没有这条反例，A 的绿证明不了任何事。
- 安全语义：登录请求走同一个 per-scan client ⇒ SSRF 校验 / scope 逐跳校验 / 限速桶照常生效；
  **凭据不落日志**（只打字段名与状态码）——两条都有源码文本守卫钉住。
- 诚实边界（刻意不做）：OAuth/JWT 刷新流、SAML、验证码、前端加密提交 —— 这些仍走
  「人工取 cookie + 静态注入」主路径。

默认限速 10 req/s · 阴性结论输出 `inconclusive` 而非「安全」· 拖库动作 UI 二次确认弹窗 · 结论可信度三态 verdict（09-29 修复：有命中不得再报阴性）

### 3.6b 批量编排与集合目标生成（2026-10-02 新增）

| 能力 | 状态 | 竞品坐标 |
|---|---|---|
| 并发池 `--concurrency` + 全局限速均分 | ✅ | ghauri `-m` 有 `--threads` 无限速均分 |
| **故障隔离**（单目标失败不中断整批、已跑完的报告照常落盘） | ✅ | **ghauri 明确短板**（"One unresponsive target can stall the entire queue"）；sqlmap 亦无 |
| 摘要**点名**失败目标与「需复核」目标 | ✅ | ghauri "no built-in reporting to aggregate results across multiple hosts" |
| 退出码三分：有高危 2 / 全批失败 1 / 其余 0 | ✅ | — |
| **集合文件 → N 个扫描目标**（Burp XML / HAR / Postman / OpenAPI **JSON 与 YAML**） | ✅ | sqlmap 2.0(WIP) 正在做 OpenAPI 目标生成；ghauri `-r` 仅单请求 |
| OpenAPI **YAML** 零依赖解析（`core/yamlLite.js`） | ✅ 子集 | 吃不下（锚点/别名/块标量）时**如实报原因 + 建议转 JSON**，绝不半解 |

- 集合条目逐个保留 method / headers / body（真靶场取证：HAR 的 POST 表单目标 `points=1 vulns=2`，
  body 保不住就会退化成 0 注入点 = 根本没测）。
- **跳过并点名**而非硬扫的三类：非 http(s) 协议（解析器经原始报文往返会把它静默补成 http）、
  multipart/form-data、无法转 JSON 的 body —— 扫出来的会是一个与抓包不同的目标，那才是假阴性之源。
- ★「0 注入点」= 一次检测都没跑 ⇒ 报告 verdict 写 `inconclusive`（此前恒写
  `no_vulnerability_detected`，把「根本没测」写成安全结论；批量里 30 个不通目标会全被读成「无漏洞」）。

## 7. 已知边界（如实声明，不做虚假承诺）

1. **9 个 template-only 库**：无真机验证，报告自动带 caveat（Oracle 已于 09-15 真机验证）。
2. **真实云 WAF**：CRS/ModSecurity 对拍通过不外推到安全狗/阿里云/Cloudflare。
3. **os-pwn / meterpreter**：设计上不做（超出工具合规边界）。
4. **MySQL 8 默认配置下 fileRead 不可用**：`secure_file_priv=NULL` 是数据库合规默认值，非引擎缺陷（沙箱已提供放行目录的验证路径）。
5. **NTLMv2 / Kerberos**：NTLM 已接；Negotiate/Kerberos 未支持。
6. **扫描事件日志撑长报告页**（E2 观察到的观感小疵）：事件流大时「查看报告」入口位置过深，未当缺陷处理。
7. **XML 通道只支持「元素 + 文本」形态**：注释 / CDATA / DOCTYPE / 正文处理指令、以及**属性位置**的
   注入面均不支持（遇到即放弃并播报）。真实 SOAP 报文（含 XML 声明）正常。
8. ~~批量多目标只做顺序编排~~ ✅ **已修（2026-10-02）**：并发池 + 故障隔离 + 摘要点名 + 集合目标生成
   均已交付（见 §3.6b）。仍存在的边界：
   - **跨目标限速仍是静态均分**（`ratePerSec / concurrency`，在批量启动时算一次）：
     per-scan 独立令牌桶**早就有**（`httpClient.forScan(scanId)` 按 scanId 建桶，
     单目标打不爆、总速率严格 ≤ `ratePerSec`）；缺的是**动态份额再分配** ——
     队列排空后剩下的目标不会自动拿回空闲份额（最后一个目标仍按 1/并发度 跑）。
     静态分配的好处是总量保证可以证明，动态分配需要运行期改桶速率，尚未做。
   - **OpenAPI 的 YAML 走零依赖子集解析器**：锚点 / 别名 / 标签 / 块标量 / 合并键 /
     TAB 缩进 / 多文档一律拒绝并给原因（半解会展开出**错的**请求，比不展开危险）。
     展开出的参数值取自 example/default，缺失处是占位符 —— 扫前须人工核对。
