## 一、一句话结论

**这是一个「验证体系」的水准明显高于「产品能力」的项目，而且作者知道这一点并写进了文档。**

它的核心资产不是检测引擎本身，而是**一套会主动揭穿自己谎言的门禁系统**：不采信组件自报状态、
拒绝静默跳过、公开作废过期结论。就工程可信度而言，它超过绝大多数同规模的个人/小团队项目，
也超过不少商业产品的工程实践。

它的天花板同样清楚：**WAF 对抗的真实战绩只有「1 个插件 / 19 条样本打穿 2 条」**，
9 种数据库只有模板没有真机证据，CI 近 12 次跑有一半是红的。
这些都不是缺陷，是**未完成的验证** —— 但对外表述时必须按这个边界说。

## 三、分维度评价

### A. 工程可信度（门禁体系） —— 9.5/10，全项目最硬的资产

不是「测试跑通了」，而是反复追问「**这个门禁真能看见它声称在管的东西吗**」，并留下疤痕：

| 已抓到的门禁谎言（仓库内有留档） | 处置 |
|---|---|
| CI job 引用不存在的文件 + `continue-on-error` → 从未拦过人 | `refs:check` + 自指注入复验 |
| `facts:check` 只比 README↔json，不校验 json 是不是当前代码采的 | 加测试文件指纹，基准过期时**拒绝** `--fix` |
| 验收报告被定向跑覆盖 → 全量结论丢失 | 报告头带版本凭证 + `N/M 跑出断言`；dirty 时自陈「不对应任何提交」 |
| 验收门禁采信套件自报 PASS | 改为**只解析可独立核对的事实数字** |
| 靶场真值清单无一致性判据 | `targets:check` 双向守卫（缺登记红 + 清单腐烂也红） |
| 覆盖率数字好看但断言不敏感 | 第二层**变异门禁** `mutation-check.mjs`：改坏一个位点测试还绿 = 该差异无人守护 |
| 测试文件写了但没接进 CI = 空转 | 每个测试文件必须有「接线守卫」断言它被真实登记 |

**判断**：这套东西的价值高于引擎本身。它把「结论与真值分处两地」这一类漂移做成了**可机械检查**的问题，
并且已经实操抓到 6 类。大多数团队一辈子发现不了其中任何一类。

### B. 检测能力 —— 8/10（有真值对照，缺严格同题对标）

- 9 条技术通道 × 18 方言 × 6 注入面；注入点发现已做到 **JSON/XML 叶子路径**、header/path、二阶跨角色
- 判定不是简单阈值：`statsHelper.js` 是**基线分布感知**（μ + z·σ）+ 一致率，抗网络抖动与动态内容
- 战绩（真 MySQL / PGlite / 真 PG）：红队 **19/19，误报 0/7**；blackbox 实战档 **13/13，误报 0/7**
- 同题对照 sqlmap：检出 18/19 vs 13/14，**误报 0/7 vs 3/4**
  ⚠️ 分母不同，比率不可直接类比 —— README 自己写了这句，是加分项

**扣分项**：没有一份「同靶点、同档位、双方各跑 3 次取中位」的定版对照。
现在的对照能说明方向（误报显著更低），但撑不起「比 sqlmap 强」的强断言。

### C. WAF 对抗 —— 诚实度 10/10，能力天花板极低且作者已量化

这是全项目最值得单独说的部分，因为它的**态度**比**结果**更有价值：

- 曾经对外声明过「真机 PL1 绕过 74 / PL3 72」，后来发现无法复现 → **主动作废并禁止引用**
- 把「放行」升级为「**打穿**」（过了 WAF **且** SQL 真执行并吐证据）→ 第一次量化出**差一个数量级**
- 真机四轮迭代：样本 8 → 15 → 19，注入点形态 1 → 3 → 5 种（按 SQL 拼接位置分，不按语言分）
- 结论（真机，PL1/PL3 同形）：**打穿插件只有 1 个，2/19；直连上界 10/19**
  编码族全部「放行但不打穿」—— 变形把 SQL 语义破坏了

**判断**：这段经历本身是极强的工程素养证据（自我推翻 + 换更严的尺子 + 公开边界）。
但**能力上确实弱**：在真实 CRS 前，tamper 库目前几乎没有实战价值。
继续堆 tamper 数量是无效投入（已在 MEMORY 里定性为死路），要提打穿链数必须动**链侧能力**。

### D. 架构与代码质量 —— 7.5/10

| 项 | 评价 |
|---|---|
| 分层 | `engine / core / api / services / config` 清晰；`detectors/` 每通道一文件，`detectorSupport/` 抽公共判据 —— 可读性好 |
| 上帝文件 | 仍有 `Exploiter.js` (57.8KB) / `extractionMaps.js` (56KB) / `Detector.js` (47KB) / `ScanManager.js` (46KB)。httpClient 四期拆分已收口（63.5→58.6KB），说明**有章法在推进** |
| 重复实现 | 历史病灶。请求解析器两份（有意，有 parity 测试钉住）、`stripEchoedPayload` 曾两份不等价已上提 `echoStrip.js` |
| 类型 | 前端 TS + 服务端 JSDoc，双端 typecheck 均 0 错误 |
| 债管理 | `arch-guard` 行+字节双判据，基线只减不增 —— 没有靠调阈值洗白 |

### E. 产品形态与交付 —— 8.5/10

- 三形态同源：Web（React+Vite）/ CLI（100+ 参数）/ 桌面（Tauri + SEA 单文件）；REST API 26 个端点
- 报告 6 格式（HTML/JSON/MD/SARIF/CSV/manifest），**同源取数**防「HTML 有、MD 没有」
- 每条漏洞必含五要素：类型(CWE·OWASP) / 等级(CVSS v3.1) / 受影响参数 / PoC(curl+原始报文) / 修复建议
- 退出码可直接进 CI 门禁（0/1/2）

**短板**：前端能力面 < CLI（`KNOWN_MISSING_UI_KEYS` 现有 **52 个**后端键无 UI 入口，只减不增有守卫）。
「同一引擎三种形态」的承诺在桌面端是打折的。

### F. 自身安全与合规 —— 8.5/10（少见地认真）

- **fail-closed 部署基线**：非回环监听且未设 token ⇒ **拒绝启动**
- SSRF 防护：内网/回环/链路本地/云元数据默认拒绝，需显式放行
- `scopeGuard`：越界目标**在发起任何请求前**被拒；重定向**每一跳**重新校验（防统一登录/CDN 逃逸）
- 桌面版：sidecar 一次性 `ENGINE_TOKEN` 经 stdout 回传，修掉了「任何进程都能连上能扫能拖库的引擎」
- 报告带 `reliability` / `dbmsEvidence.caveat` / `constraints`；**目标不可达时拒绝输出「未检出」**

### G. 文档 —— 7/10（内容极好，体量失控）

- 64 篇 `docs/*.md`，实测口径、修复记录、失效声明齐全，**会主动标注「本段数字已作废」**
- `TODO.md` 1,368 行按优先级 + 依赖前提 + 验证口径维护，已完成项留档防回归
- **负担也是真的**：`CHANGELOG.md` 2,840 行；已多次踩「文档现状段系统性过期」（MEMORY 里列为硬约束：开工前必须读码核实）
- `readme:check`（36KB 脚本）+ `facts:check` 把 README 数字钉住，这是**体量的解药**，但仍然需要人工维护大量散文

### H. 性能 —— 7.5/10（有量化手法，无端到端基线）

- 手法优秀：记录型 stub 顶替 `httpClient`，**无网络/无 DB** 精确计数，突破「性能结论要靶场」的死结
- 本次实测 `npm run perf:budget`：**96 请求**（最小配置 + 安全点；union 8+1 / error 45+13+2+1+1 / boolean 6+2+2 / inline 1+1 / nosql 12+1）
  其中「跨检测器字节级完全相同」的重复请求只有 1 种 × 5 份 = **5.2%**（上界）
- ⚠️ 口径更正：MEMORY.md 曾记「最小配置 111 / 默认 148」，但这两个数字**从未写进 README**（`grep` 已确认），
  与本次 96 的差异属**配置口径不同**而非文档漂移 —— 上一版评价里写「README 写 111/148」是**我的误指，此处更正**。
  真实缺口是：**README 完全没有性能章节**，请求预算这个可量化优势对外不可见
  —— **已修（`f623114`）**：新增「性能」章节（手法 / 复现命令 / 未采样通道 / 优化纪律 / sqli-labs 速度对照），
  刻意不写死数字（会漂移），改为给命令 + 参考量级
- 曾推翻自己的推断（以为跨检测器重复 10–15 次，实测 1 种 × 5 份 = 5.2%，错一个数量级）
- 缺口：只有单点下界，没有「整站扫描耗时/请求量」基线；优化验收含 WAF 场景这条纪律已立

### I. 作为求职作品的竞争力 —— 8.5/10

**能打的点**（面试可讲 60 秒）：
1. 真机验证闭环：真 MySQL / 真 PG / 真 SQL Server 2022 / 真 Oracle 26ai / 真 ModSecurity 容器
2. 会主动作废自己的结论（有留档，不是嘴上说）
3. 门禁可信度建设：变异测试、接线守卫、事实断言门禁 —— 这是**架构师级别**的话题
4. 全栈三端同源 + 报告工程化（SARIF/CVSS/CWE）

**风险**（必须提前准备说辞，否则被问死）：
- README 里「禁止对外引用」出现 5 次以上。面试官只读 README 会得出「什么都没证明」的印象。
  → **准备一段把「诚实的边界」讲成优势的话术**，并主动给出「已证明的部分」清单（见第二节 2.4）
- 「9 种数据库只有模板」容易被读成「支持 18 种」→ 主动声明，别被发现
- 简历上不要写「对标 sqlmap 90% 功能」这类无法量化的话；写「红队靶场 19/19、误报 0/7（含 sqlmap 同题对照）」

## 七、只做三件事的话

1. **定义「批次收口清单」并写进 CONTRIBUTING**
   后端加键 → 前端接线 → `facts:refresh` → `facts:fix` → lint → 提交。
   **半批不提交。** 这一条能一次性干掉复发率最高的问题（本次三处红全是它）。
