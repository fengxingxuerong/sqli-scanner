## 二、六步流程（可复用）

### 第 0 步：先看这文件拆过没有

大文件往往已拆过，只是主文件仍显胖。查文首/中部注释：

```js
// [大文件拆分 2026-09-14] 盲注/时间/内联已抽至 blindExtractor.js
```

有 → **接续**，沿用它的手法，别在仓库里搞出第二套拆分风格。

**顺带验证旧方案的结论是否还成立**：`runScanLoop-拆分方案` 里写着「detect.js ⛔ 评估后建议不做」，
但 `scan/detect.js` 早在 2026-09-13 就被做了。**过期结论比没结论更坏**，已在原文档订正。

### 第 1 步：找"不可动的钉子"（最容易翻车）

四类钉子，逐一 grep：

| 类型 | 侦察命令 | 处置 |
|---|---|---|
| ① 测试直接打桩的私有方法 | `grep -rn "\._rawUndici\|\._guessColumnsCached" tests/` | 保留方法名（薄委托） |
| ② 被 re-export 出去的符号 | `grep -rn "from '.*xxx.js'" src/ tests/` | re-export 保路径 |
| ③ **测试读源码文本解析常量** | `grep -rn "src/api/\|src/engine/" tests/ \| grep -iE "read\|url\|match"` | **字面量必须留在原文件** |
| ④ 高内聚编排方法（反复 `this.` 互调） | 按方法体统计 `this.` 引用 | 不拆 |

**③ 是本轮新发现的一类，比 import 更难绕**（详见 §三）。

### 第 2 步：用耦合度**实测**选簇，别照抄清单

写脚本按方法体花括号配平 → 统计 `this.` 引用去重数，升序排：

| this 引用数 | 判定 | 实例 |
|---|---|---|
| **0** | 纯函数，直接搬 | `_staticSentinel` / `_normalizeForStatic` |
| 1–2（簇内互调） | 可搬，外部依赖用**依赖注入** | 预过滤簇（依赖 `_mapPool`） |
| 3–10 | 谨慎 | — |
| **37** | 别硬搬 | detect 段（当年判"不做"） |

> **判据**：静态耦合计数是**风险提示，不是"不做"的充分理由** —— detect.js 后来靠引入
> `run` 上下文对象还是做了。但它确实选对了**优先级**：先做低耦合的。

**别信印象里的候选清单**：第五刀开工前实扫 `git ls-files`，发现
`api/scanRoutes.js`(1059)、`payloadRegistry.js`(983)、`Exploiter.js`(969) 都不在我上一轮的清单里。

### 第 3 步：搬移时保住"零行为变化"

三条硬手段：

```js
// (a) 同名薄委托 —— 调用方/打桩测试/子类覆盖零影响
_finishResponse(res, opts) { return finalizeAxiosResponse(res, opts); }

// (b) re-export 保路径
import { esc } from './reportHtml.js';
export { esc };
// ⚠ 若本文件内部也要用，必须再写一条 import —— `export ... from` 不产生本地绑定

// (c) 依赖注入替代 this 外传（用 getter，让测试替换后仍生效）
get _prefilterDeps() { return { mapPool: this._mapPool.bind(this) }; }
```

**拆成两个模块破循环依赖**（第四刀）：reportPoC 要用 `esc`，而 ReportGenerator 又要
import reportPoC → 环。把纯函数下沉为叶子模块后依赖单向：
`reportHtml（叶子）← reportPoC ← ReportGenerator`。

### 第 4 步：每搬一块立即验证（不要攒）

```bash
npx eslint <改动文件>        # 立刻抓"搬走后没人用"的残留 import（本次共抓 8 个）
node --test tests/<相关>.js   # 最小相关集
npm run typecheck:server      # ★搬移也会引入类型回归
```

**lint 是这里性价比最高的自动检查**：逻辑搬走后主文件里的 import 就成了 unused，
`no-unused-vars` 一次报出。

### 第 5 步：给外移模块补直接单测 —— 并做缺陷注入

**不补单测，等于只做了搬运工。** 补测的价值在于：原来只能靠端到端间接验证的边界，
抽成纯函数后可以穷举（如"内网地址要不要生成链接"，此前要起真靶场观察）。

**写完必做缺陷注入** —— 详见 §四。

### 第 6 步：收紧架构门禁基线

本项目是「基线锁定 + 只减不增」（`scripts/.arch-baseline.json`）。瘦身后**必须下调基线**，
否则容差被反向利用。目前基线内仅剩 1 条：`httpClient.js 1223 行`。

## 三、★本轮最大发现：源码文本解析型钉子★

第五刀侦察 `api/scanRoutes.js` 时发现：3 个守卫测试**硬编码读源文件文本**并用正则提取常量。

```js
// tests/configReachability.guard.test.js:49
const ROUTES_SRC = read('src/api/scanRoutes.js');
const KNOWN = setMembers(ROUTES_SRC, 'KNOWN_CFG_KEYS');

// tests/configWhitelist.guard.test.js:22
const src = readFileSync(new URL('../src/api/scanRoutes.js', import.meta.url), 'utf8');
const m = src.match(/const KNOWN_CFG_KEYS = new Set\(\[([\s\S]*?)\]\)/);
```

**后果**：`KNOWN_CFG_KEYS` / `BACKFILL_SCALAR_KEYS` 的**字面量必须留在 scanRoutes.js** ——
re-export 救不了，因为测试读的是**文本**不是模块。

**连带约束**：`sanitizeStart`（539 行巨型函数）依赖这些常量。搬走它就会形成
「新模块 import 常量 ← scanRoutes 又 import 新模块」的**循环依赖**；
除非改这 3 个防漂移门禁的文件路径（那属于改门禁，风险高一档）。

→ **决策：这一对不拆，改拆另两簇。**

> **教训**：钉子侦察不能只 grep `from 'xxx.js'`，还要 grep **文件名字符串本身**。
> `read('src/api/...')` / `new URL('../src/api/...')` 这类依赖比 import 更隐蔽。

## 四、缺陷注入：两种假阴性

**不做缺陷注入，"测试全绿"什么都证明不了。** 五刀共做 15 例注入，其中 3 例最初是假阴性。

### 假阴性类型 A：注入脚本没生效

```bash
# ✗ sed 转义易失真；node replace 不匹配也不报错；多处替换只校验第一处
sed -i 's|...|...|' src/mod.js

# ✓ 逐处校验 + 注入后 grep 确认目标串消失
const rep = (from, to) => {
  if (!s.includes(from)) throw new Error('MISS: ' + from);   // 不匹配就抛错
  s = s.split(from).join(to);
};
rep(A, a); rep(B, b);          // 每一处都校验
fs.writeFileSync(p, s);
```

> 实例：注入「删除两道长度防线」，第二处模式含 `\n` 未匹配却静默跳过，脚本仍打印 OK →
> 测试全绿，我一度误判为"覆盖缺口"。加逐处校验后正确报红。
> **"测试没报红"要先怀疑注入没生效，再怀疑测试空转。**

### 假阴性类型 B：断言验证的是结果，而结果不由被测代码保证（更隐蔽）

```
源码注释称：safeHref 剥控制字符是为防 `java\nscript:` 绕过。
注入：把 .replace(/[\u0000-\u0020\u007f]/g,'') 换成 .trim()
结果：22 个用例全绿 —— 因为 `java\nscript:` 是由**协议白名单** ^https?:// 拦住的，
      跟剥不剥控制字符无关。
```

10 个 A/B 对照用例里**只有 1 个**真有差异：`https://example.com/a\u007fb`
（协议合法、路径内混了控制字符）。

> **判据（写断言前必问）**：*「删掉被测的这一行，这条断言还会不会绿？」*
>
> **副产品**：这类对照常常暴露**注释在吹牛**。此时保留代码（它可能仍有其它作用），
> 但把注释和测试改成如实描述 —— 不要继续传播错误的安全叙事。

### 注入要挑**契约层行为**，不是语法层

**最有价值的一例**（第二刀）：把「提取失败 → 静默返回 fallback」改成「直接抛错」，
**86 个 extractor 用例 86/86 全绿 —— 抓不到**。这条关键契约（低权限账号枚举
`information_schema` 报错时不降级就会中断整个扫描）**此前零覆盖**。
补测后重做同一注入 → 8/3 报红。

> **跑绿 N 个用例 ≠ 这段逻辑被验证过。** 找覆盖缺口就问：这段代码的**契约**是什么？
> 改坏哪一行会让用户看到错误行为？注入那一行。

## 五、踩过的坑（逐条，带实例）

| # | 坑 | 实例与修法 |
|---|---|---|
| 1 | **常量大小写 + 比对取小写 = 永不匹配** | `CREDENTIAL_HEADERS=['Authorization']` 却 `includes(k.toLowerCase())` → 凭据剥离静默失效。被新写单测抓出。常量统一小写。 |
| 2 | **测试断言对象搞错 = 空转** | 传同一引用时函数克隆副本，断言原对象等于断言了个寂寞。改为断言**返回值**。 |
| 3 | **合并两份实现要挑更严的那份** | 两通道凭据剥离不一致（H1 漏删小写 `authorization` → 凭据泄露）。采用更严的 H2 行为，注明"属收紧非放宽"。 |
| 4 | **别为让门禁变绿而删步骤** | `cargo clippy` 抛 rustc ICE（1.98.0），已证 `src-tauri/` 零改动 → 如实记为工具链问题，**不注释掉 `lint:rust`**。 |
| 5 | **自洽型门禁防不了"两处一起旧"** | `facts:check` 只校验 README ↔ `_facts.json` 自洽，不比对实测 → 加了 60 个用例它仍绿。**必须定期 `--refresh`**。 |
| 6 | **给旧代码补 JSDoc = 开类型检查** | 第五刀 typecheck 报 6 处：历史调用点真传 `undefined` 作默认值。修法是**放宽标注匹配真实用法**，不是改调用点。 |
| 7 | **区段删除锚点选远了会吃掉无关方法** | 终点锚点在 347 行，而 `_attachPoc`(303)/`_enrich`(338) 落在区间内 → 会被误删。**好在脚本在写盘前抛错**。锚点必须落在紧邻的下一个符号。 |
| 8 | **注释是待验证假设，不是事实** | 三处旧注释被实测推翻：`--dump-format` 声称"由 dumpData 调用"实为零调用点；"命名加别名避免冲突"实为无别名；"控制字符剥离防 XSS"实为白名单在拦。 |
| 9 | **标准库行为别想当然** | `encodeURIComponent("'")` === `"'"`（单引号是 URI 合法字符）；`Number('') === 0` 是有限数（不走 def，被钳到下界）。都用 `node -e` 验过再写断言。 |

## 十、第六刀（2026-09-25 追加）：拆的理由不是体积，是「第二条入口没设防」

| 项 | 值 |
|---|---|
| 提交 | 本地 `72e322c`（远端等价快照 `c610030`） |
| 文件 | `api/scanRoutes.js` 1190 → 589 行（**-601**） |
| 拆出 | `api/scanConfigGuard.js:buildGuardedConfig`（536 行守卫整段平移）+ 随块的 `PARAM_DEL_ALLOWED` / `EXTRACT_SCOPE_MODES` / `sanitizeIdentList` / `sanitizeExtractScope` |
| 服务端用例 | 2355 → **2361**（新增 6：`api.entryParity` 4 + `report.summaryCounts` 2），fail 恒 0 |

**与前五刀的关键差别：这一刀不能只看体积。** 直连分支（`mode:'direct'`）在 `sanitizeStart` 里是
早退分支，返回的 config 曾是 `{...defaults, ...cfg}` —— 那 536 行 clamp 一条都没走
（实测 `concurrency:9999` / `timeoutMs:99999999` / 带分号的 `dumpWhere` 原样进引擎）。
所以拆的判据是「**两条入口必须走同一个函数**」，而不是「文件太长了」。

**整段平移的前置核法**（这一条值得复用）：先用脚本把块内**用到的顶层标识符**列出来
（忽略注释行，否则会误收只在注释里出现的名字），确认块内只依赖 `cfg` / `config` /
`scopeRules` 与模块级导入 —— HTTP 专有的 url/method/params 处理全在块外，才能整段搬。
核完才动手，实际搬到 eslint 时只暴露了两个漏网的模块级常量（`EXTRACT_SCOPE_MODES` /
`PARAM_DEL_ALLOWED`），说明「先算依赖」这一步是真的有效。

**这一刀撞到的新知识点：文本型守卫会被搬移咬。** 三处按源码文本定位 clamp 收敛点的守卫
（`docs.configDefaults` / `configReachability.guard` / `configDroppedKeys.warn`）当场红。
处置口径：**把文本扫描范围扩成「入口层这一整簇」（并读两个文件）**，不是放宽判据 ——
这类守卫的价值恰恰是「名单被改名/挪走时先红」。

**验收协议（第七节那四条）逐条跑过**：`server npm test` 2361 条 0 失败 · `typecheck` +
