## 一、结论先行

**能真实做事的部分：检测 + 拖库（union 通道）在真实 MySQL / PostgreSQL 上跑通，CLI 与引擎一致，速度比 sqlmap 快一个数量级。**
**不能当真的部分：① MySQL 拖库行数据错位（会把错误数据写进交付报告）；② 225 个 tamper 的"WAF 绕过率"是自写正则模拟器测的，遇到严格 CRS 基本无效；③ 文件读写 / UDF / os-shell 全套接管能力只有 mock 单测，零真实 DBMS 验证。**

| 能力 | 判定 | 实测证据 |
|---|---|---|
| 漏洞检测（union/error/boolean/time/stacked/二阶） | ✅ 可用 | 真实 MySQL 9/9 PASS；真实 PG 8/8 PASS；CLI 一致；本地 19 场景 19/19（**须清代理**，见 P0-0） |
| 自动 DBMS 指纹 | ✅ 可用 | 两个真库均自动识别为 MySQL / PostgreSQL，未手工指定 |

| 结论可信度守卫 | ✅ 实战价值高 | 目标异常时输出 `verdict=inconclusive / reliable=false`，拒绝下阴性结论 |

## 三、按作战优先级列出的问题

### P0-0 — 出网代理吞掉本地/内网扫描，且失败被记作"无漏洞"（本次新发现，实测）

- 现象：引擎默认 `trustProxyEnv`，命中系统 `HTTP_PROXY` 后**连 127.0.0.1 的目标也走代理**；代理对 `POST /store` 失败时，该点被记为"已检测、0 漏洞"，而不是"不可判定"。
- 危害：**假阴性**——在装了 Clash/公司代理的机器上扫内网，代理一抽风就是一片"干净"报告。这比漏检更危险。
- 另一面：连续 5xx 时守卫是生效的（我误配靶场连接池时，报告正确给出 `verdict=inconclusive / reliable=false`）——**零星网络失败没被覆盖**。
- 修法（按性价比）：
  1. `core/httpClient.js` 默认把 `localhost/127.0.0.1/::1/内网段` 加进 NO_PROXY（可配 `proxyBypassLocal`）；
  2. 网络失败返回 `{status:0, __netErr}`（前轮 P0-1 已列），检测器遇 `__netErr` 抛 `INCONCLUSIVE` 而非判负；
  3. 报告 `summary` 里给 `netErrPoints` 计数，UI 明示"N 个点未完成有效检测"。

### P0 — 会写进交付文档的错误

**3.1 MySQL 拖库行切分错位（本次新发现，实测）**
- 现象：多行列值被并进同一行（`username` 字段里出现第 2 行的 `email`），且只产出 1 行。
- 危害：客户拿报告去核库，会发现"表里只有 1 个用户、密码为 admin123"——**结论方向对，数据全错**，比漏检更伤信任。
- 复现：`e2e/diag/live-dump-mysql.mjs`（已随本文档保留），对 `/num?id=1` 开 `enableExtract`。
- 修法建议：`Exploiter.js` MySQL 分页/GROUP_CONCAT 拼接路径加**行数自检**（落地行数 vs `COUNT(*)`），不一致即降级逐行；行分隔符改用不可见多字符组合并转义；单测用 ≥5 行中文+特殊字符表做 golden。

**3.2 默认跨库拖库（授权面风险）**
- 实测：`--dbs` 与提取都把同实例的 `netsec` 库一并拖出（8 张表，含 `vulnerabilities`/`assets`）。
- 现状：`scopeGuard` 只按 host/重定向管边界，**不管 schema**。
- 建议：新增 `extractScope.allowedDatabases`，默认只拖注入点所在库；跨库需显式 `--dump-all` 并在报告首屏标注。

### P1 — 影响检出与可信度

**3.3 WAF 绕过能力与实际不符**
- 实测（真实 OWASP CRS v4.1.0 规则，自实现执行器，≈PL3）：

| 场景 | tamper 关 | tamper 开 | 结论 |
|---|---|---|---|
| num | boolean | boolean | 无增益 |
| str | 0 检出 | 0 检出 | 全拦 |
| like | 0 检出 | 0 检出 | 全拦 |
| orderby | 0 检出 | 0 检出 | 全拦 |
| blind | boolean | boolean | 无增益 |

- 而 `e2e/waf-lab/results/validate.md` 里的"107/225 有效、base64encode 100% 绕过"，靶场是**手写的正则模拟器**（`e2e/waf-lab/waf-profiles.js`，规则就几条 `/union\s+select/i`）。
- 建议：README 里把"225 tamper"与"WAF 绕过率"解绑标注口径；真实绕过能力用 `e2e/waf-real`（官方 CRS 原文）作为唯一对外数字，并补 `--waf-real` 回归。

**3.4 接管能力零真实验证**
- `server/tests/exploiter*.test.js` 全部注明"mock extractor，不触真实目标"。
- `fileRead/fileWrite/osShell/udf/registry` 的能力矩阵（`TAKEOVER_CAPS`）是**按 DBMS 文档声明**的，未在真实库上跑通一条。
- 建议：至少在真实 MySQL（有 FILE 权限）上跑通 `fileRead` 一条闭环；跑不通就在 README 标"实验特性"。

### P2 — 工程与边界

- OOB：本地监听 53/80 可用，实战需公网 IP + 域名 NS 委派，否则 time/oob 场景恒不出结果。
- `enableDestructivePayloads()` 生产代码无调用点（前轮审计已指出），`risk=3` 语义空转。
- 二阶检测会发**真实写请求**，需与 `productionMode` 二次确认绑定（现状只有 warn 日志）。

## 附录：修复记录（2026-09-09 03:30，全量验收见各条）

### F1. P0-0 代理假阴性 —— 已修复
- `core/httpClient.js`：新增 `isLocalOrPrivateHost()`；`resolveProxy()` 对 localhost/127/8、10/8、172.16/12、192.168/16、169.254/16 默认**不吃环境变量代理**（`proxyBypassLocal` 默认 true，显式 `config.proxy` 不受影响）；API 白名单/透传、CLI `--proxy-bypass-local/--no-proxy-bypass-local` 同步接入。
- `core/scanValidityGuard.js`：新增 `isNetworkFailureError()` 与 `addNetworkErrorPoint()`；`summary.counts.netErrPoints`、存在未决点时 `reliable=false` + 专属 reason/advice。
- `engine/scanRunner.js`：`runLayer` 区分「网络层失败」与「检测器不适用」，全层网络失败 → 该点记未决（不再写成「已检测、无漏洞」）。
- 验收：带系统代理跑 `e2e/detection-runner` = **19 PASS / 0 FAIL**（修复前 18/1）；`e2e/diag/neterr-sporadic-check.mjs` 交替掐断场景 verdict=inconclusive / netErrPoints=1。

### F2. MySQL 拖库行切分错位 —— 已修复（并挖出 3 个连带真库级缺陷）
- `engine/extractionMaps.js`：MySQL/HSQLDB/H2 的 `GROUP_CONCAT` 显式 `SEPARATOR`（行分隔 0x1E）；**真库实测发现 `SEPARATOR CHAR(30)` 在 MySQL 8.0.28 是 1064 语法错误（只收字面量）** → 用 `0x1E`；堆叠路径 `SEPARATOR 0x0A` 同理。
- **分页语义修复**：`LIMIT/OFFSET`（及 MSSQL OFFSET-FETCH、Oracle ROWNUM、Sybase TOP、Firebird ROWS）原本作用于**聚合结果（恒 1 行）**——真库上第 2 页起恒为空、第 1 页实为整表聚合再被 group_concat_max_len 截断。全部方言分页下推进子查询（先取源表行，再聚合）。
- NULL 安全：`CONCAT_WS` 会跳过 NULL 参数导致列位左移 → 新增 `escColsNN()/escColsNNJoin()/nullSafeQuoteCol()`（MySQL IFNULL/PG COALESCE/MSSQL ISNULL/Oracle NVL）。
- 验收：`e2e/real-mysql-lab/dump-correctness.e2e.mjs`（真 MySQL）多行/中文/逗号竖线/换行/NULL/单引号/OFFSET 分页/空表 **8/8 PASS**；真 MySQL 全链路拖库 `users` 5 行、`products` 4 行、`audit_logs` 8 行逐行正确（修复前 users 落 1 行且串列）；真 PG 拖库 4 行正确；单测 `dumpRowSplit.sqlshape.test.js` 7 条锁死 SQL 形状。

### F3. WAF 绕过口径 —— 已解绑
