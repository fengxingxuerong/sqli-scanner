## 三个结论

1. **旧首选链真机现形**：dash2hash×hexliterals 在真 CRS PL1 下 0 打穿 0 放行。本地自实现
   口径（PL1 放行、tamper on 5/5）与真机天花板存在实测背离——「本地绿」对这条链不构成
   真机承诺。
2. **unionvaluesrow 系链是唯一真机有效形态**：补位插件（dash2hash/hexliterals）不增不减
   打穿数（2/19 持平）。⚠️ 曾据此把它提为 wafRecommend 通用第一顺位，被 artifact-drift
   门禁**当场抓到回归**：multi-engine PL1 lab 的 tamper 腿在 H2/HSQLDB 上 union 技术丢失
   （VALUES ROW 是 MySQL 8 语法）——通用链表必须服务所有 DBMS，已回退顺序、证据保留本文。
   待办：DBMS 感知的链选择（确认目标方言后再启用 unionvaluesrow 系）。
3. **scalarselectinline 链内不帮不碍**（2/19 持平），作为标量子查询消 SELECT 的备选组件
   保留；单独使用真机全拦（错误注入形态还剩 AND/extractvalue/引号指纹）。

## 口径

- 打穿判定只采信 MySQL 自己生成的证据（结果集标记 / MySQL 报错短语），回显不算。
- 直连上界 10/19 = 本批样本不经 WAF 真正取到数据的条数，是打穿率的真分母。
- 「放行(自实现≈PL3)」列是 crs-engine 默认档；真机 PL1 与自实现 PL3 并排阅读时注意档位差。
