# 自定义检测条目（`--payload-file`）

> 2026-10-09（批次 D24）新增。定位：**给内置注册表打补丁的官方扩展点** —— 对标 nuclei 的自定义模板，
> 但刻意做得比它小：只支持**追加**，不支持覆盖、不支持逻辑、不支持外链。

## 为什么需要它

内置注册表（`registry.json` 681 条 + `registry.versioned.json`）覆盖通用场景，但真实业务里总有
内置库覆盖不到的东西：某个中间件的特殊报错形态、某个 WAF 放行但本仓没收录的语法、某个国产库的
版本特性语法。在 D24 之前，唯一的扩展点是 `--tamper <file>.js`（`args.js` 的 `resolveTamperPlugins`），
它只能加**变换**，加不了**检测条目** ⇒ 想多测一条自己的 payload 只能改代码再发版。

## 用法

```bash
node scripts/one-click-scan.mjs -u "http://target/page?id=1" --payload-file ./my-payloads.json
```

文件格式与 `server/src/engine/payloads/registry.json` **同 schema**（数组，每条一个对象）：

```json
[
  {
    "id": "acme-oracle-wrapper",
    "dbms": ["Oracle"],
    "technique": "error",
    "level": 2,
    "risk": 1,
    "clause": ["where"],
    "boundary": ["'", ")", ""],
    "template": "{ORIG}' AND 1=CTXSYS.DRITHSX.SN(1,(CHR(60))) AND '1'='1",
    "falseTemplate": "{ORIG}' AND 1=2 AND '1'='1",
    "where": "value",
    "note": "某客户环境自研 wrapper 下的报错形态"
  }
]
```

| 字段 | 必填 | 说明 |
|---|:-:|---|
| `id` | ✅ | 唯一；**不得与内置条目同名**（冲突即拒绝加载） |
| `dbms` | ✅ | 非空数组，取值见 `DBMS_LIST` |
| `technique` | ✅ | 必须是 `TECHNIQUE_TYPES` 之一（union/error/boolean/time/stacked/oob/second_order/inline） |
| `template` | ✅ | 真模板，`{ORIG}` 为原值占位 |
| `falseTemplate` | 推荐 | 布尔假对；布尔通道缺它则无法成对判定 |
| `level` / `risk` | 可选 | 缺省按 **1** 补全（保守档），不是"不过滤" |
| `clause` / `boundary` | 可选 | 缺省 `[]` |
| `where` | 可选 | `value`（默认）或 `position` |
| `minVersion` / `maxVersion` | 可选 | 版本区间，语义同内置条目 |

## 三条硬约束（不是建议，是写进代码的）

1. **只追加，不覆盖。** `id` 与内置条目冲突 ⇒ 报错退出（exit 2）。
   理由：让一个外部文件能静默改掉内置条目 = 把"基线能力"交给用户磁盘上的一份文件，
   报告里的证据等级也就无从谈起。
2. **自定义条目同样受高危池硬门管辖。** 判定复用 `isDestructivePayload()`（按**模板串**比对，
   不靠 id 是否含 `-dest-`）⇒ `productionMode` 未确认时它们一样不投放，不会因为"用户自己写的"就绕过去。
3. **校验失败即硬失败。** 文件不可读 / JSON 坏 / 字段缺失 / `technique` 越界 / 文件内 id 重复，
   一律打印原因并 exit 2，**不降级为"忽略继续扫"** —— 静默忽略会让用户以为自定义生效了，比报错危险。

## 作用域与边界（诚实口径）

- **仅本次扫描生效**：条目通过 `AsyncLocalStorage` 注入（与高危池策略同构），不写回任何文件、
  不进进程级全局 ⇒ REST 侧并发扫描互不污染。
- **不传 `--payload-file` 时逐位零变化**：`activeRegistry()` 直接返回内置数组**同一个引用**，
  注册表指纹测试与 facts 数字都不受影响（有单测钉住，见下）。
- ⛔ **未接 UI / 未接 REST**：目前只有 CLI 入口（面板与 `/api/scan` 都没有这个参数）。
  这是刻意的范围控制，不是遗漏 —— 接 UI 需要同步前端契约测试与配置键登记，另起一批。
- ⛔ **不改报告里的证据等级**：自定义条目参与筛选与投放，但不改变 `dbmsEvidence` 的分档口径。
