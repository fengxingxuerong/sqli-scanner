## 批次 3 · WAF 链侧能力：搜索器补「减标点补位 + 三链组合 + 有序去重」

评价文档定性「提打穿链数必须动链侧，不是再写第 229 个 tamper」。本批在 A2 架构内修生成器
的三个质量缺口：

1. **dash2hash 进不了候选池**（covers=0 被 `.filter(covers>0)` 挡住）—— CRS 标点预算方向
   唯一实证有效项从生成器里整体消失。修法：消除者/减标点补位分池，补位只作第二三槽位、
   不占定向名额、两序都生成。
2. **被拦词族 ≥3 时双链覆盖不满** —— 每类别取最优消除者再跨类别组三链
   （不能用 pool 前 3 名两两配：quote 被拦时前几名可能全是 LITERAL 类 ⇒ 三链恒空）。
3. **去重键用排序集合** —— 变换复合不可交换，两个顺序被折叠成一条
   （`push` 与 `mergeCandidateChains` 两处；后者此前连静态表自己的两种实证顺序都吃掉一半）。

验证：39/39 单测（+4 新用例，注入复验杀 3）；`waf-bypass-search` e2e ✅（A=2/B=0/预算 6:6）；
`waf-real` PL1 对外口径零变化；`tamper-matrix` exit 0。

**回归排查留证（waf-auto PL1）**：本机跑 `CRS_PL=1 npm run waf-auto` 得自动技术位 0
（CI #133 同套件=8）。做了对照实验——把 searcher 换回批次 C 前版本重跑：**同样 0**
⇒ 不是批次 C 引入的回归，是本机实验室（本地 MySQL 8.0.28 + 本机扫描动力学）与 CI
（8.0.46 + 服务化初始化）的既有差异。批次 C 改的只有「第 3 个验证名额（生成链）」的内容，
静态前两名的选取与排序零改动；CI #134 的 acceptance 将给出批次 C 在 CI 侧的实证结论。

## 批次 D3 终审 · scalarselectinline 真机结果：未打穿（诚实留证）
