# D260 · 服务端覆盖率门禁的确定性收口

> 2026-11-06。原始输出见 [`覆盖率门禁-D260-真机记录-2026-11-06.txt`](覆盖率门禁-D260-真机记录-2026-11-06.txt)。
> 本页只讲「为什么红、怎么校准、边界在哪」，不做任何能力声明。

## 1. 起点

D259 收口时 `npm run gate:close` 51/51 全绿，但 CI 的 `Server coverage gate` 仍 `exit 1`：
`all files | 89.11 | 73.18 | 81.83`，`73.18% branch coverage does not meet threshold of 74%`。
这是本仓第 5 次「门禁只活在别处」：那道门禁只在 `ci.yml` / `ci-local.mjs` 里跑，收口清单看不见。

D259 把根因写成「全量多进程 coverage 合并口径」，并试了三条修法（补测、纯函数化、归因实验），
都没拉回。D260 接手后先做了**推翻**，再改口径。

## 2. 推翻链（旧结论保留，标注作废）

| 阶段 | 结论 | 现状 |
|---|---|---|
| D259 | 合并口径把新分支算进分母不进分子；补测可拉回 | **口径过粗**，保留原文 |
| D260 初版 | 「带 `?query` 的隔离实例不被归因 ⇒ 把补测搬进同进程即可」 | **已推翻**：补测后复跑仍 `exit 1` / 73.18%，ReportAI.js branch 仍 34.56% |
| D260 定稿 | 只要任意进程加载了带后缀（`?` / `#`）的模块 URL，同一源文件的多进程快照合并就**不再 union** | 最小样本双版本复现，见下节 |

两份测试文件的初版注释都已就地标注作废并保留（不删历史）。

## 3. 最小复现（不依赖本仓，可独立跑）

```bash
mkdir -p /tmp/covprobe && cd /tmp/covprobe
printf '%s\n' "export const f=x=>x>0?'pos':'neg';" "export const g=x=>x?'a':'b';" "export const h=x=>x===1?'one':'other';" > mod.mjs
printf '%s\n' "import {test} from 'node:test';import assert from 'node:assert/strict';import {f} from './mod.mjs';test('t1',()=>assert.equal(f(1),'pos'));" > t1.mjs
printf '%s\n' "import {test} from 'node:test';import assert from 'node:assert/strict';import {g,h} from './mod.mjs';test('t2',()=>assert.equal(g(1),'a'));test('t3',()=>assert.equal(h(2),'other'));" > t2.mjs
printf '%s\n' "import {test} from 'node:test';import assert from 'node:assert/strict';import {h} from './mod.mjs?x=1';test('t4',()=>assert.equal(h(1),'one'));" > t3.mjs
N=/c/Program\ Files/nodejs/node            # CI 同款 Node 24；本机默认是 22
for i in 1 2 3 4 5; do $N --experimental-test-coverage --test --test-coverage-include='mod.mjs*' --test-concurrency=1 t1.mjs t2.mjs 2>&1 | grep 'mod.mjs   |'; done
for i in 1 2 3 4 5; do $N --experimental-test-coverage --test --test-coverage-include='mod.mjs*' --test-concurrency=1 t1.mjs t2.mjs t3.mjs 2>&1 | grep 'mod.mjs   |'; done
```

| 组合 | Node 22.22.2 | Node 24.22.1（CI） |
|---|---|---|
| 无后缀实例 | 5/5 次 `57.14% branch / 100% funcs`（union） | 3/3 次同值（union） |
| 含 `?query` 实例 | 5 次里 3 次 `66.67% / 33.33%`、2 次 `57.14% / 100%`（随机） | 6/6 次 `66.67% / 33.33%`（稳定单快照） |
| 含 `#fragment` / 同进程混合 | 同样退化 | 同样退化 |

结论：**不是补测不够，是合并退化成单快照**。与测试写在哪个文件无关。

   - **双向校验**排除名单：新增未排除 ⇒ 红；名单里的文件不再含后缀 ⇒ 红；文件数 <400 ⇒ 红。

## 7. 边界

- 81.78% 是**校准后测量集**的 branch 覆盖率，不是「代码质量一夜提升 8.6pt」，也不是能力结论。
- 测量集比全量少 5 个测试文件；对外引用覆盖率数字时必须带上这句。
- 没降低阈值、没缩小 include、没放宽任何断言；这是**合并口径校准**。
- 结论仍受 `AGENTS.md §3.5` 永远质疑协议约束：门禁绿 ≠ 判据对。
