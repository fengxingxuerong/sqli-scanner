# SQL 注入检测工具「sqli-scanner」— P2 增量 PRD（仅变更部分）

> 作者：产品经理 许清楚（Xu）
> 版本：P2 增量（基于已交付完整版 v1.0.0）
> 语言：简体中文
> 配套架构背景：`docs/system_design.md`（完整版）

---

## 1. 增量概述

在已交付完整版（v1.0.0，已覆盖 URL 扫描/四类注入检测/数据库指纹/列类型枚举/数据提取/可视化报告 + Web& Tauri 双形态）之上，P2 新增 5 项增强能力：**代理支持（F-14）、自定义请求头与认证（F-15）、WAF 规避（F-16）、历史扫描记录持久化管理（F-17）、暗色主题切换（F-18）**，全部为"用户侧可用性 / 隐蔽性 / 持续使用体验"增强，不涉及检测算法与核心数据流重写。

## 2. 变更点清单

| 编号 | 变更描述 | 影响模块 | 验收标准 | 风险等级 |
|------|----------|----------|----------|----------|
| F-14 | 代理支持（HTTP / SOCKS）：在 `ScanConfig` 已预留的 `proxy` 字段上落地真实透传，所有扫描出站请求经用户配置的上游代理发出；支持 HTTP 与 SOCKS5 两种协议。 | 两者（前端配置录入 + 引擎 httpClient 透传） | ①可在扫描配置中填写 HTTP 代理地址（host:port）并生效，抓包可确认全部请求经代理发出；②支持 SOCKS5 代理协议；③代理配置并入 `ScanConfig`，可随扫描配置一起持久化（与超时/并发等一同保存/读取）。 | 中 |
| F-15 | 自定义请求头 / 认证：落地 `ScanConfig` 已预留的 `auth` 字段并复用现有 `headerParams`，使扫描可携带登录态或自定义 Header 访问需鉴权目标。 | 两者（前端录入 + 引擎请求头合并） | ①可填 Basic Auth（用户名/密码），自动生成 `Authorization` 头并随每次请求发送；②可填自定义 Cookie 字符串，随每次请求发送；③可填任意自定义 Header 键值对，随每次请求发送；④上述配置随扫描配置保存。 | 中 |
| F-16 | WAF 规避：提供可独立开关的 3 种基础规避策略——随机 User-Agent 池、请求间随机延时（jitter）、Payload 混淆（大小写随机化 / 内联注释分割）。 | 两者（前端开关组 + 引擎 httpClient 与 payloads 应用） | ①随机 UA：每次请求从内置 UA 池随机选取；②请求间随机延时：按配置 jitter 区间（如 0–2s）随机等待后再发下一请求；③Payload 混淆：对发出 Payload 做大小写随机化及/或内联注释（`/**/`）分割；④三项均提供独立开关，默认**全部关闭**；⑤开启后检测稳定性下降时可随时关闭恢复。 | 低 |
| F-17 | 历史扫描记录持久化管理：将首版"内存 Map + 可选导出"升级为自动持久化的本地历史库，支持回溯与删除。 | 前端为主（HistoryPage + 本地存储） | ①每次扫描完成自动存入本地（localStorage 或本地 JSON 文件，不加密）；②HistoryPage 列出全部历史任务（目标/时间/结果摘要）；③点击某条可回溯查看其完整报告；④可删除单条记录（删除后不再出现于列表）。 | 低 |
| F-18 | 暗色主题 / 界面个性化：在 MUI 主题层提供浅色/暗色切换并持久化。 | 前端为主（App 顶层 ThemeProvider + 顶栏切换按钮） | ①顶栏提供主题切换按钮；②切换即改变 MUI `ThemeMode`（light/dark）并持久化到 localStorage；③全站配色（含 MUI 组件与 Tailwind 布局区域）跟随主题，无裸露未适配样式。 | 低 |

## 3. 对旧架构的影响与风险

### 3.1 接入点（基于完整版已预留设计）

| 变更 | 接入旧模块 | 说明 |
|------|------------|------|
| F-14 / F-15 代理与认证 | `server/src/core/httpClient.js` + `ScanConfig`（已预留 `proxy`/`auth`） | 完整版 §0 明确"`HttpClient` 与 `ScanConfig` 预留 `proxy`、`auth` 字段接口"，§7 共享知识"`httpClient` 代理/认证字段预留"。只需在 httpClient 的 axios 实例上落地 `proxy` 配置（HTTP 用原生 `proxy` 选项，SOCKS5 需引入 `socks-proxy-agent` 挂到 `httpAgent/httpsAgent`），并将 `auth` 转译为 `Authorization` 头、合并进请求头集合。前端 `TargetForm`/`ScanConfigPanel` 增加录入项，`shared/types.ts` 类型放宽即可，**无需改 REST 契约**（`/api/scan/start` 的 `config.proxy`/`config.auth` 字段已存在）。 |
| F-15 自定义 Header | `Target.headerParams`（已存在）+ `auth` | 完整版 `Target` 已含 `headerParams`，只需确保这些 Header 与 `auth` 生成的头在**每个**出站请求（检测器/指纹/提取器统一走 httpClient）被合并发送。 |
| F-16 WAF 规避 | `httpClient`（UA/jitter）+ `payloads.js`（混淆） | 随机 UA 与 jitter 在 httpClient 请求前/间施加；Payload 混淆在 `payloads.js` 发送前对模板做变体生成（完整版 §8 已说明"Payload 模板结构预留混淆位"）。规避开关作为 `ScanConfig` 新增字段（建议 `wafEvasion: { randomUA, jitterMs, obfuscate }`），随配置透传。 |
| F-17 历史记录 | `pages/HistoryPage`（已存在）+ 本地存储 | 完整版 HistoryPage 与 `scanStore` 已存在（内存 Map + 可选导出）。P2 将"导出"升级为"自动持久化"：扫描完成时把 `ReportModel` 快照写入本地存储；HistoryPage 改为从持久化源读取，并增加"删除单条"。 |
| F-18 暗色主题 | `App.tsx` 顶层 `ThemeProvider` + 顶栏布局 | 完整版 §8 已说明"预留 `theme` 切换位，P2 再加"。在 `App` 顶层用 MUI `ThemeProvider` + `createTheme`，读取 localStorage 决定 mode；顶栏放切换按钮；Tailwind 布局区域用 MUI `useTheme`/`sx` 或 CSS 变量跟随，避免硬编码颜色。 |

### 3.2 兼容 / 回归风险

- **回归风险（中）**：F-14/F-15 改动了 httpClient 与请求头合并逻辑——这是所有检测器的**唯一**出站通道（§7 约定检测器不得自行 axios/fetch）。改动必须通过"无代理/无认证配置时行为完全不变"的回归验证，否则影响既有 GET/POST/Cookie 扫描与四类检测的正确性。
- **检测稳定性风险（中）**：F-16 的 Payload 混淆与 jitter 可能改变请求时序与 Payload 形态，理论上影响布尔/时间盲注判定（时间盲注对延迟阈值敏感）。因此**默认关闭**是关键护栏；开启后应在报告中标注"规避已启用"，便于结果复现。
- **存储兼容风险（低）**：F-17 引入持久化历史。需定义历史记录存储 key 与 schema 版本，避免旧版内存/导出 JSON 结构不一致导致 HistoryPage 解析异常；删除为软性（仅移除列表项，不破坏其他数据）。
- **主题适配风险（低）**：F-18 若 Tailwind 布局区域使用硬编码颜色值，暗色模式下会出现"亮底亮字"不可读。需核查 `className` 中的硬编码色值，统一改为随主题变量。MUI 组件本身多主题自适应，风险主要在 Tailwind 自定义色块。
- **双形态一致性（低）**：Web 版与 Tauri 版共用一份前端代码。F-17 的"本地文件系统"在 Web 版受浏览器限制，应统一走 localStorage 优先（必要时 Tauri 版经 `tauriBridge` 落盘文件），保证两套形态业务逻辑一致、仅落盘通道不同。
- **依赖新增（低）**：F-14 SOCKS5 需新增 `socks-proxy-agent`（仅服务端）。其余变更不引入新依赖或仅用 MUI 既有能力。

### 3.3 不在本次范围（明确排除，避免范围蔓延）

- 不改动检测算法、Payload 库主体、四类检测逻辑、数据库指纹、列类型枚举、拖库逻辑。
- 不做代理凭证加密、不做历史记录加密（明确不加密，见 §4）。
- 不做多目标批量扫描、不做云同步历史（仍为单机本地）。
- 不做"规避效果评估 / 自适应 WAF 对抗"（仅提供手动基础开关）。

## 4. 待确认问题（已给默认决策，不必回问用户）

| # | 问题 | 默认决策 |
|---|------|----------|
| ① | SOCKS5 是否首版必做？ | **做**。实战中大量目标经 SOCKS 代理（内网/跳板），仅支持 HTTP 代理会显著削弱 F-14 价值；SOCKS5 仅需新增 `socks-proxy-agent`，成本可控。 |
| ② | 代理凭证是否持久化？如何存？ | **随配置持久化，明文存本地不加密**；UI 在代理/认证配置区明确提示"凭证以明文保存于本地，请勿在公共设备使用"。与完整版"历史/配置不加密"的安全基调一致。 |
| ③ | 历史记录用 localStorage 还是文件系统？ | **首版统一用 localStorage（简单优先）**；Web 版天然支持，Tauri 版也先用 localStorage 保证业务逻辑零分支；后续若需更强持久性，可经 `tauriBridge` 升级为本地 JSON 文件，属后续增强而非 P2 必做。 |
| ④ | WAF 规避默认关闭是否合适？ | **合适，默认关闭**。规避会改变请求形态与时序，可能降低检测稳定性与结果可复现性；应作为"需要时显式开启"的可选项，且开启后在报告中标注。 |
| ⑤ | 暗色主题默认态？ | **默认浅色，并支持"跟随系统"**。首版默认浅色（与完整版一致）；提供"跟随系统 / 浅色 / 暗色"三态，其中"跟随系统"读取 `prefers-color-scheme`，用户手动切换后覆盖并持久化。 |
