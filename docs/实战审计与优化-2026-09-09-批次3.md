## 一、本批已落地

### P1-A 时间模板「静默缺失」守卫（#23 深化）
- **核查**：文档所指 5 条缺 `{SLEEP}` 的 SQLite 模板已修复（lite-time-106 已带 {SLEEP}）。
- **深挖**：盘点全部 407 条 time 模板（扁平 + TIME_VECTORS + 注册表），发现**真正缺位的是 `-dest-` 误归类向量**：
  - `pg-time-dest-2` `pg_read_file('/etc/passwd')`、`pg-time-dest-3` `lo_import('/etc/passwd')`——文件读/OOB 误标成 time，
    小文件读取无延迟（时间检测恒不命中），且 `lo_import` 还会在目标库写对象；
  - `ora-time-dest-1` `UTL_HTTP.REQUEST(...)`——OOB 向量误标成 time。
- **修法**：改为真延迟向量——PG 用核心函数 `pg_sleep(5)`（pg_catalog 原生，无需扩展、无副作用）；
  Oracle 改 `DBMS_PIPE.RECEIVE_MESSAGE('sqli',5)`。
- **守卫**：`tests/payloads.timeGuard.test.js`——所有 time 模板必须含 `{SLEEP}` 或明确的固定延迟/重运算语义
  （RANDOMBLOB/BENCHMARK/REPEAT/GET_LOCK/DBMS_PIPE/WAITFOR/pg_sleep/sleep N/heavy 笛卡尔积），
  禁止「无占位符且无语义」的静默缺失模板进回归；并锁定本批三条修复锚点。

### P1-B 报告摘要可见性：skippedPoints 汇总（#5）
- **问题**：点级 skipReason 已有，但 `report.summary.skippedPoints` 未落地——交付报告看不到「有多少点没测、为什么没测」。
- **修法**：`scanHelpers.summarizeSkipped(points)` 纯函数（按原因聚合 total/byReason），scanRunner 报告收尾写入
  `report.summary.skippedPoints`。可单测 + 复用。
- **测试**：`tests/reportSummary.visible.test.js`。

### P1-C OOB 不可用标注（#7）
- **问题**：oob 被选中但接收端启动失败只 warn，time/oob 场景的「无带外」被误读成「无漏洞」。
- **修法**：启动失败记录原因，报告收尾写入 `report.summary.oobUnavailable = { reason }`。
- **测试**：随 reportSummary.visible.test.js 的汇总契约（引擎侧分支由 scanRunner 集成覆盖）。

### P1-D 容量退避后动态降并发（#6）
- **问题**：decideBlockPolicy 回 Retry-After 退避后，本轮剩余重跑恢复原并发 → 目标限流/过载下「退避 → 高并发 → 又退避」抖动。
- **修法**：退避结束后复用 db-guard 的 `schedulerRef.concurrency=1` 模式（不动令牌桶，零回归面），
  本轮剩余重跑保持低并发；并发变更随 `waf_block_policy { action: 'slowdown' }` 事件可见。

### P1-E 统一错误响应可见性：X-Error-Code 头（#12 第一步）
- **问题**：业务错误全部 HTTP 200 + code，监控/网关/代理看不到失败率，curl `set -e` 拦不住。
- **修法**：响应后置中间件（app 最前，逆 CSRF/token/路由之前安装）——所有 `code !== 0` 的 JSON 响应自动携带
  `X-Error-Code` 头（`code=0` 为成功约定，health 不误伤）。HTTP 状态码不变（前端已依赖 200+code），
  第二步灰度切状态码待前端侧改造后单独做。
- **测试**：`tests/api.errorHeader.test.js`（403/415 带头、health 不带头）。
  - 实现弯路记录：patch 中间件初版放在安全头之后，排在逆 CSRF（403/415）之后 → 未覆盖早期错误响应；已移到 app 最前。
