## 一、一句话结论（更新）

**早版的核心判断仍然成立 —— 最硬的资产是「验证体系」而不是「检测引擎」；但当天下午的推进把

- 严格同题对标（早版列为 P2-12 未动）：**23/23 = 100% vs sqlmap 14/23 = 60.9%**
- 性能端到端基线（早版 §H 缺口）：**整站 2.675s vs sqlmap 30.3s（同机 11×）**
- CI 红率（早版列为风险 #2）：近 10 次 **8 绿 2 红**，#133 曾 12/12 全绿

唯一没变的是**工作节奏病**：半批不收口**第三次复发**，此刻仍是红的。

## 五·补 口径更正：`--crawl` 不是空壳（2026-10-04 更正，本文 §四 #6 作废）

本文初版写下「**`--crawl` 是空壳**：`args.js` 解析了参数，引擎层 `grep -c crawl` = 0」——
**这条是错的**，来源是照抄了 10-03 的一条未核实结论，没有回源码看。实际回码核实：

| 层 | 事实（文件:行） |
|---|---|
| 参数解析 | `server/bin/cli/args.js:57`（`--crawl-browser`）；`scalarsCore.js:194` 解析 `crawlDepth`（0–3） |
| 默认值 | `config/defaults.js:314` `crawlDepth: 0`（默认关闭） |
| **消费点** | `engine/TargetParser.js:200-215` — `crawlDepth > 0` ⇒ `_crawlLinks()`；`crawlBrowser` ⇒ `_crawlBrowser()` |
| 实现 | `engine/crawler.js`（187 行，导出 `LinkCrawler` / `extractLinks` / `attrValue`）+ `engine/discovery/browserCrawler.js`（headless 版，playwright 不可用时降级） |
| 测试 | `server/tests/browserCrawler.test.js` |
| 附带 | `bin/cli/advise.js:152` 对 `--crawl` 给「扩大攻击面、可能触及未授权路径」的风险提示 |

⇒ 爬虫**已实现且接通**，覆盖「正则 HTML 爬取」与「SPA headless 渲染」两条路，且 `crawlDepth` 已与
`--level` 解耦（`TargetParser.js:192-199` 有专门的修复记录：原门槛 `level>=5` 会让它静默不生效）。

★ 教训（本项目第三次同类）：**「现状」类结论必须回源码核实，不能沿用文档/记忆里的旧判断。**
本仓的文档与记忆都存在系统性过期，且这次连我自己前一天写的评价都成了过期源。
