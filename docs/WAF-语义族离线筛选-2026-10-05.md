# WAF 语义族离线筛选（2026-10-05）

> 目的：回答「真机打穿链数为什么上不去」。方法**纯本地**（CRS 规则 + JS 执行器），
> 无需 ModSecurity 容器、无需数据库，一条命令可复现。

```bash
npm run waf:screen                       # 默认基线 + PL1/PL3
node scripts/waf-semantic-screen.mjs --base="1' AND SLEEP(5)-- -" --pl=1,2,3,4
```

## 为什么要做这个

真机四轮 ModSecurity CRS 实测（2026-09/10）留下的两个数字互相矛盾：

- 编码族（如 `encode2hex`）：**放行 19/19**，但**打穿 0/19** —— 过了 WAF，SQL 却执行不了；
- 语义保持类（`symboliclogical` 的 `&&`/`||`）：语义不变，但 CRS 942120 正则直接含这两个符号
  ⇒ PL1 下就是负收益（`EVIDENCE.CRS_NEGATIVE`）。

⇒ 于是怀疑「打穿链数低」不是搜索器排序的问题，而是**候选池本身没有既保语义又能过 CRS 的族**。
本筛选就是把这件事**离线算清楚**，不再靠猜。

## 方法

1. **基线自检（fail-closed）**：基线 payload 必须**在各目标档位都被拦**，否则「变换后放行」毫无意义。
   脚本依次试候选，取第一个各档均被拦的；都不被拦 ⇒ **拒绝产出报告**。
   ⚠️ 首次跑就踩了这个坑：`1' AND 1=1-- -` 在 **PL1 本就放行** ⇒ 整表「放行」全是噪音。
2. 对 `CORE_SEMANTICS` 全部 **46 个族**：`applyTampers` 变换基线 → 送 `e2e/waf-real/crs-engine.js`
   判 PL1 / PL3 是否放行（942 家族规则）。
3. 「语义保持」按 `SEMANTIC_CATEGORIES` 的**人工精标**判定：
   `syntactic` / `lexical` / `whitespace` / `literal` 是，`encoding`（传输层编码）不是。

## 结果（基线 `-1' UNION SELECT 1,2,3-- -`，PL1=拦 / PL3=拦）

| 类别 | 族数 | PL1 放行 | PL3 放行 |
|---|---:|---:|---:|
| syntactic（语法等价） | 15 | 0 | **0** |
| lexical（词法拆分） | 13 | 1（`keywordinterleave`） | **0** |
| whitespace（空白替换） | 7 | 3 | **0** |
| literal（字面量编码） | 5 | 0 | **0** |
| **encoding（传输编码，不保语义）** | 6 | 3 | **3** |

- **语义保持 且 各档均放行的族：0 个。**
- PL3 唯一放行的三个族 —— `charunicodeescape` / `base64encode` / `hexentities` —— **全是 encoding 类**。

## 结论：与真机数据的交叉验证成立

| 证据源 | 结论 |
|---|---|
| 真机（modsec-live，真 MySQL + CRS 容器） | 编码族放行 19/19、**打穿 0/19**；打穿插件仅 1 个 / 2–19 条 |
| 本次离线筛选（本地 CRS 执行器） | PL3 下语义保持类**无一能过**；唯一能过的正是那批编码族 |

两侧指向同一件事：**PL3 下能过 CRS 的变换，恰好都是破坏 SQL 语义的那批** ⇒ 过了 WAF 也拼不出
可执行的 SQL。这就是「打穿链数」天花板的机理，不是搜索器排序能救的。

由此得到的三条判断：

1. **继续堆 tamper 数量是无效投入**（与既有定性一致，现在有了全族扫描的数据支撑）：
   46 个族里没有漏网的「语义保持 + 放行」候选，靠增加同类形态不会改变这个结论。
2. **要提打穿链数，只能造新的语义保持变换** —— 既不在 CRS 词表里、又保持 SQL 语义的写法
   （这是研究型工作，不是调参）。
3. **对外口径**：WAF 对抗应定位为「辅助能力」，不应作为产品差异化卖点
   （真机打穿 1 个插件 / 2–19 条；评分维持 4.5）。

## 口径纪律（别把这份报告误用）

1. **「放行」≠「打穿」**。本脚本只判**有没有被 CRS 拦**；SQL 是否真能执行、能否吐出证据，
   只有真机（容器 + 真 MySQL）能判，本脚本**不产出该结论**。
2. 执行器是 ModSecurity 规则的 **JS 复现**，一致率由 `npm run waf-fidelity` 守
   （942 家族当前 99.6%），且只覆盖 **query / 表单 body**（XML 接口未覆盖，别外推）。
3. 「语义保持」来自 `CORE_SEMANTICS` 的**人工精标**，是本脚本的输入不是输出。
4. 基线换掉、CRS 版本换掉、档位换掉，结论都可能变 ⇒ 引用时必须带上本次的基线与 `--pl` 参数。
