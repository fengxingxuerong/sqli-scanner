# sqli-scanner 全方面优化方案（渗透实战视角）

> 撰写视角：以「拿这个工具去打真实授权目标」的渗透工程师立场，回答一个问题——
> **离「实战一把梭」还差什么，按什么顺序补。**
>
> 依据（全部为本仓库已有实测结论，非想象）：
> - `docs/实战渗透实测评估-2026-09-10.md`：pentest-lab 11 场景 + sqlmap 对拍
> - `docs/待办盘点-2026-09-12.md`：55 处未完成标记盘点
> - `docs/发布就绪度评估-2026-09-18.md`：v1.1.0 验收实测
> - `docs/vs-sqlmap-analysis/`：13 份对标分析
> - 代码现状：`server/src/engine/`（9 检测通道）、`core/tamper/`（228 脚本）、`core/waf/`
>
> 定位判断：本工具已是「无 WAF 环境下快速普查 + 拖库 + 出报告」的合格工具；
> **但真实目标 90% 前面有东西（云 WAF / 安全狗 / 宝塔 / 自研正则），当前版本在这类目标上全通道交白卷**。
> 所以本方案的核心思想不是「再加功能」，而是把主战场从「无防护靶场」搬到「有防护的真实目标」。

## 〇、现状一句话与核心矛盾

| 维度 | 现状（实测口径） | 实战含义 |
|---|---|---|
| 无防护检出 | 10 场景 9 检出，union 100–400ms，误报 0 | 普查可用 |
| 拖库正确性 | 真 MySQL 6 行全对（中文/引号/跳号/逗号） | 可交付 |
| **WAF / 关键字过滤** | **全通道 0 检出；手工 `\|\|` 3 秒绕过** | **主战场失守** |
| tamper 链 | 228 个脚本，但 5 组链实测**零增益** | 有弹药没枪法 |
| 头注入 / LIMIT 位 / 空基线 | 仅 error 通道兜底 | 非常规位置半残 |
| 11 个 DBMS 模板库 | 无真机验证（README 已声明 ⛔） | 非 MySQL/PG 目标靠运气 |
| 后渗透 | fileRead/Write 真闭环；UDF/os-shell 实验级 | 检出≠拿下 |

**核心矛盾：引擎的「检测逻辑」是健全的，但「对抗逻辑」是缺失的——
它会把 payload 发出去，却不会在被拦之后像人一样想「换个说法再试」。**

手工渗透遇到 403 的本能反应是：换等价语法 → 换编码 → 换通道 → 换位置。
引擎目前这四步全没有自动化。这就是 P0 的全部意义。

## 一、优化总纲：四条战线

```
战线 A（对抗）：WAF 之下把检出做回来          —— 决定工具在真实目标上的生死
战线 B（深度）：检出之后把利用做透            —— 决定报告能不能换成成果
战线 C（广度）：更多位置、更多库、更多协议     —— 决定适用面
战线 D（工程）：速度、OpSec、测试、架构        —— 决定能不能规模化、可信赖
```

优先级排序原则：**先补「人工 3 秒能做、引擎做不到」的（性价比最高、最伤口碑），
再补「人工也要花时间」的，最后补「锦上添花」的。**

## 二、战线 A · P0：WAF 对抗体系（本期最大工程）

> 实测锚点：pentest-lab `waf403` 场景 3 次重复 0 检出；`waf-bypass-proof.mjs` 证明
> `id=1 || 1=1`（6 行回显）vs `id=1 || 2=1`（1 行回显）手工可判。
> **漏掉的不是难洞，是 3 秒钟的洞。这是口碑级缺陷。**

### A1. 语义等价变换库（bypass 的「弹药库」）

现状：`core/tamper/plugins/` 228 个脚本照搬 sqlmap，是「字符级混淆」思路
（大小写、编码、注释替换）。对现代关键字 WAF，更有效的是**语法级等价变换**。
新建 `core/waf/bypass/semantics.js`，按 DBMS 组织变换原语：

| 类别 | 变换示例（MySQL 为主） | 针对的过滤 |
|---|---|---|
| 逻辑算符 | `AND`→`&&`、`OR`→`\|\|`、`NOT`→`!`、`XOR` 冷门化 | 关键字黑名单 |
| 比较算符 | `=`→`LIKE`/`RLIKE`/`REGEXP`/`<=>`/`<>` 取反、`>`→`BETWEEN` 取反 | `=` 检测 |
| 空白符 | 空格→`%0a`/`%0b`/`%0c`/`%a0`、`` ` ``包裹、括号贴合 `1=(SELECT...)`、内联注释 `/**/`、版本注释 `/*!50000*/` | 空白/词边界检测 |
| 函数等价 | `SUBSTRING`→`MID`/`SUBSTR`/`LEFT`+`RIGHT`、`ASCII`→`ORD`/`HEX`、`SLEEP`→`BENCHMARK`/`GET_LOCK`、`|0x`| 科学计数法 `1e0` | 函数黑名单 |
| 字符串构造 | 无引号字符串：`0x61646d696e`、`CHAR(97,100)`、`CONCAT` 拼接、动态执行 `PREPARE`（堆叠场景） | 引号/字符串特征 |
| 数字构造 | `1`→`1e0`/`0b1`/`.1e1`/`TRUE`、算术展开 `2-1` | 数字特征 |
| 语句结构 | `UNION SELECT`→`UNION ALL SELECT`/`UNION DISTINCT`、`,`→`JOIN`（commaless 已有，整合进来）、`ORDER BY` 位用 `CASE WHEN` | 语句级特征 |
| 协议层 | HPP 参数污染（`id=1&id=2`）、分块传输、charset 混淆（`ibm037`/`utf-7` 场景化）、JSON 编码包裹（`{"id":"1"}` vs 数组/数值型） | WAF 解析差异 |
| 数据库差异 | MySQL 反引号、PG `$$` 美元引号、MSSQL `[]` 括号、`;%00` 截断 | 库特性逃逸 |

**验收**：`e2e/pentest-lab` 的 `waf403` 场景（`\|\|` 可绕）引擎自动检出 boolean；
`bl` 黑名单场景从「仅 error」提升到 union+boolean 检出；每个变换原语配单测。

### A2. Bypass 自动搜索器（bypass 的「枪法」）

现状：tamper 是「人肉选链、静态应用」，实测 5 组链零增益——因为**不知道目标拦什么**。
人手工的做法是：先发探针看拦哪个词，再针对性变异。把这个过程自动化，
新建 `core/waf/bypass/searcher.js`：

1. **拦截画像**（`wafProbe` 增强）：对注入点发一组「单词探针」
   （`and` / `select` / `union` / `sleep` / `(` / `'` / 空格 / 逗号…每个独立成包），
   记录哪些触发 403/406/自定义页 → 得到**目标的黑名单词表**。
2. **定向变异**：只从 A1 库里选「不含被拦词」的变换组合，而不是盲试 228 个 tamper。
3. **真假差验证**：每个候选必须过「真值 vs 假值回显差」验证（复用 boolean 判据），
   通过才算数——防「绕过了 WAF 但语法错了」的假阳性。
4. **组合搜索**：单变换不行再两两组合，预算封顶（默认 ≤40 请求/注入点，可配）。
5. **结果固化**：成功的变换链写入 `manifest.json` 与报告「WAF 交战记录」，
   让报告读者能复现每一步（现在报告已有交战记录框架，把搜索结果接进去）。

**验收**：pentest-lab `waf403` 在 ≤40 请求内自动找到 `\|\|` 路径并确认 boolean 注入；
waf-lab / CRS 靶场旁路率（见 §九 KPI）有基线数字并可回归。

### A3. 通道降级与转移策略

被拦时的决策树（`engine/scan/detect.js` 编排层实现）：

```
常规通道被拦
 ├─ 报错通道还活着？→ 收窄到 error（现状已有，保持）
 ├─ 内容被过滤但延迟不拦？→ 转 time（SLEEP 被拦就用 BENCHMARK/GET_LOCK 重负载向量）
 ├─ 页面完全无差异？→ 转 OOB（`oobTrigger` 目前只是预留开关，`config/defaults.js:276`，本期落地）
 └─ 全部不可行 → 输出 inconclusive + 具体建议（已有，保持「不谎报安全」这条生命线）
```

### A4. 真实 WAF 靶场扩容（没有靶场的优化都是玄学）

现有 waf-lab / waf-real / CRS 等价校验是字符级靶场。补：

- **CRS 全档矩阵**：ModSecurity + OWASP CRS v4.x，paranoia level 1–4 全跑（现只测了部分档）。
- **国产 WAF 特征库**：安全狗、宝塔防火墙、云锁的公开规则整理成 `e2e/waf-real/rules/`
  （注意版权：只收录公开/逆向自公开规则集的特征，不搬运商业规则全文）。
- **云 WAF 免费档实测**：挑 1–2 家提供免费版的云 WAF，挂真实域名做季度手工实测，
  结果记入 `docs/waf-runbook.md`（已有此文件，扩成「各 WAF 交战手册」）。
- **绕过回归基线**：每个 WAF 靶场记录「当前旁路率 x/y」，CI 防回归。

## 三、战线 A 延伸 · P0：检出正确性补齐（已实测漏检的位置）

### B1. COLLATE / 集合运算提取模板（待办盘点 D1，实战价值最高）

- 缺口：`engine/extractionMaps.js` 有 ORDER BY，**无 INTERSECT / EXCEPT / COLLATE**。
- 实战场景：MySQL `Illegal mix of collations` 是 UNION 注入第一高频报错，
  缺 `COLLATE` 模板等于放弃所有「表字段 collation 与库默认不一致」的注入点
  （老库、混合字符集库极常见）。
- 做法：`extractionMaps.js` 每库补 `COLLATE` 包裹变体；MSSQL/PG 补 `INTERSECT/EXCEPT` 提取路径。
- 验收：real-mysql-lab 加一个 `utf8mb4_general_ci` vs `utf8mb4_bin` 混合靶点，UNION 提取成功。

### B2. 头注入与非常规位置全通道化

- 现状：UA 头注入、LIMIT 位、过滤/编码位**仅 error 通道命中**（pentest-lab #1/#3/#10）。
- 根因：union/boolean 通道的 payload 模板按「标准 query 参数」假设构造，
  对 UA（长字符串上下文）、LIMIT（数字裸位、不可用引号）未做上下文适配。
- 做法：
  - `engine/payloads.js` 按「注入上下文」（字符串/数字/裸关键字位/日志型长文本）分族，
    LIMIT 位专配无逗号、无引号变体（`CASE WHEN`/`PROCEDURE ANALYSE` 历史形态）；
  - `UnionDetector`/`BooleanBlindDetector` 的候选按上下文过滤后再试，而非一套打天下。
- 验收：pentest-lab `ua`/`limit`/`bl` 三场景从「仅 error」到 ≥2 通道命中。

### B3. 空基线场景的通道退化修复

- 现状：参数原值查不到行时（已删除的 id），boolean/union 失效只剩 error（pentest-lab #8）。
- 实战价值：列表页点过期链接、爬虫喂来的失效 URL 是批量扫描的常态，
  空基线残废 = 批量场景召回腰斩。
- 做法：boolean 判据从「与基线比」扩展为「三值比较」（真值/假值/基线三方对比，
  真≠假即候选，基线只作参考）；union 在空基线时直接用 `ORDER BY` 猜列 + 标记行探测。
- 验收：pentest-lab `empty` 场景 boolean 恢复命中；误报对照 `safe` 保持 0 检出。

### B4. DBMS 版本分支 payload

- 现状：只识别版本号，不按版本切 payload（`docs/vs-sqlmap-analysis/08-*` P2-2）。
- 实战例子：MySQL 8 的 `information_schema` 变化、`JSON_TABLE`；PG 15 的 `pg_read_file` 权限收紧；
  MSSQL 2017+ 的 `sys.fn_xe_file_target_read_file` OOB 路径。版本对了，利用路径完全不同。
- 做法：`DBFingerprinter` 拿到版本后写入扫描上下文，`payloadRegistry` 增加
  `minVersion/maxVersion` 过滤维度。
- 验收：mock MySQL 5.1 vs 8.0 指纹结果，payload 池有可见差异；版本未知时回退全量（现状）。

## 四、战线 B · P1：利用深度（从「检出」到「拿下」）

### C1. OOB 通道实战化（最高优先）

- `oobTrigger` 预留开关落地：检测段内容/延迟全被过滤时自动尝试 OOB 触发向量
  （MySQL `LOAD_FILE`/`INTO OUTFILE`+DNS、MSSQL `xp_dirtree`、Oracle `UTL_HTTP`、PG `COPY`）。
- `core/oobReceiver.js` 增强：DNS 子域长度截断容错（63 字节/标签）、
  分片重组、HTTP/DNS 双通道互备、外网 receiver 与内网自建 receiver 双模式。
- 验收：oob-real-lab 全库种真闭环；waf403 场景在全内容过滤变体下经 OOB 确认注入。

### C2. 利用决策树自动化

检出注入后自动回答渗透工程师的下一串问题（`Exploiter.js` 编排）：

```
当前用户？→ 是否 DBA/写权限？→ 堆叠可用？→ secure_file_priv？→ 插件目录可写？
   │              │                │              │                  │
   ├─ 非 DBA：专注拖库，自动枚举库/表/列（已有，提速即可）
   ├─ 可写 + 路径已知：fileWrite → 写 shell / 写计划任务（实验→正式）
   ├─ DBA + 堆叠：UDF 提权链（udf-lab 已有真机验证基础，从实验转正式）
   └─ MSSQL：xp_cmdshell 检测 → 启用 → 执行回显（OLE/sp_OA 仅桥接的现状写明边界）
```

每一步的结果写进报告「攻击路径」段（见 §六 D2），让报告自己讲故事。

### C3. 拖库工程化

- **断点续拖**：`blindExtractor` 已按位推进，加持久化进度（scanLedger 已有落盘能力），
  中断后 `--resume` 从断点继续（实战大表拖一半被 WAF 踢掉是常态）。
- **增量拖库**：`scanDiff.js` 已有扫描 diff，扩展到数据层——只拖新增行
  （按自增 id / 时间戳列，`--freshness` 语义对齐 sqlmap）。
- **大表策略**：行数估算 → 分页并行 → 盲注时优先「条件过滤后拖感兴趣行」
  （`--where` 支持），避免对千万行表发起灾难性逐位推断。

### C4. 二阶注入深化

`SecondOrderDetector` 已支持跨角色双身份。补：
- **触发页自动发现**：写入后自动爬站内候选回显页（同 scope 内），
  而非要求人工指定 trigger URL；
- **多跳二阶**：A 写入 → B 列表触发 → C 详情二次触发的链路建模（真实 CMS 常见）。

## 五、战线 C · P1：覆盖广度

### D1. 注入点发现能力（决定「扫得到」）

- **Crawler 升级**（`engine/crawler.js`）：
  - 表单自动识别与填充提交（`docs/vs-sqlmap-analysis/11-crawl-forms-*.md` 已有分析，落地）；
  - JS 渲染可选模式（无头浏览器插件化接入，重目标才开）；
  - 参数挖掘：历史参数词表（commonNames.js 扩展为 Arjun 级词表）+ 响应内隐藏参数提取。
- **请求源解析**（`core/requestFileParser.js` 扩展）：
  - 现状支持的格式之上，补 **Burp XML 导出、HAR、OpenAPI/Swagger JSON、Postman Collection**——
    实战交付的起点永远是「客户给的 burp 包」，这一步顺滑度决定第一印象。
- **新上下文**：XML/SOAP body 叶子、GraphQL（query 内变量与内联参数）、
  multipart 文件名字段、JWT claim 值（签名照算场景）。

### D2. 认证与会话实战化

- **NTLMv2 / Negotiate(Kerberos)**：`core/ntlmAuth.js:22` 已声明不支持，
  微软系内网目标（SharePoint/Exchange/域内系统）直接劝退，补 NTLMv2 是内网实战刚需。
- **会话保鲜**：登录态失效自动重登（`csrfKeeper`/`sessionStore` 已有骨架，
  加「登录脚本」配置：表单重登 / API 重登 / token 刷新三种模式）；
- **MFA/验证码**：明确声明边界 + 提供「人工过验证后导入 cookie」的引导流（UI 层）。

### D3. 11 个未验证 DBMS 的真机验证矩阵

- 现状：SQL Server / Oracle / TiDB / DM8 / ClickHouse / DB2 / Sybase / Firebird /
  Informix / Access / MonetDB 模板库无真机验证（README ⛔ 档）。
- 做法（按实战遇到频率排序）：**MSSQL → Oracle → TiDB → ClickHouse → DM8** 先行，
  全部 Docker 化进 `e2e/multi-engine-lab`（已有此目录与 mssql-lab/oracle-lab），
  每库至少跑通：指纹 + error + union + boolean + time 五件事。
- 验收：每过一库，README 三档分层从 ⛔ 升级，报告 `dbmsEvidence.caveat` 相应收敛。
- 成本提示：DB2/Sybase/Informix 镜像难搞，可长期挂 ⛔，诚实标注比假装支持强。

## 六、战线 D · P1/P2：工程能力

### E1. 性能与规模化（P1）

- **请求预算与自适应限速**：目标出现 429/503/WAF 页面时自动降速退避
  （`scanGovernance.js` 扩展），反之畅通时提速——现在是固定速率，要么打残目标要么浪费窗口期。
- **批量模式**：目标列表文件输入 + 资产级并发调度（多目标间并行、单目标内串行），
  普查场景刚需；配合 `--known-point` 直通报备过的注入点跳过发现段。
- **进度可观测**：CLI 增加实时 ETA 与请求计数（现在 `--quiet` 之外信息颗粒度粗）。

### E2. OpSec 与合规护栏（P2，但渗透工程师必须关心）

- **流量拟人**：UA 池轮换、请求间隔抖动（jitterMs 已有配置，加「工作时间段模拟」档位）、
  顺序随机化——对抗基于时序/频率的检测。
- **出口管理**：socks5/http 代理链支持、每 N 请求切换出口、Tor 兼容说明
  （`egressOpts.js` 扩展，写明「代理不保证匿名」的诚实声明）。
- **破坏性操作隔离**：`payloads/destructive.js` 已存在，确保所有写库/写文件动作
  必须显式 `--risk 3` + 二次确认 + 报告留痕；默认只读这条红线写进架构守卫
  （`arch-guard` 加规则，防未来重构引入默认写操作）。
- **授权护栏审计**：scopeGuard / SSRF 防护 / 重定向逐跳校验已是亮点，
  补「扫描前授权声明确认书」导出（manifest.json 已有字段，生成可签字的 PDF 页）。

### E3. 报告与交付（P2）

- **攻击路径叙事**：把 §四 C2 决策树的执行结果渲染成「从注入点到影响面」的链路图
  （mermaid/图表演染进 HTML 报告），客户看到的是故事不是列表。
- **一键复现包**：每条漏洞附带可执行的 `poc.http`（REST Client 格式）+ curl 命令
  （`pocBuilder.js` 扩展），交付后客户 30 秒复现。
- **风险量化**：漏洞条目映射 CVSS 3.1 向量（CWE-89 已有，补 CVSS 计算与业务影响说明模板）。
- **管理层摘要**：报告首页 5 行话版（发现了什么/能拿走什么/怎么修/优先级），
  技术细节下沉——现在报告偏工程师视角。

### E4. 测试基础设施（P2，质量的保险丝）

- **真实 CMS 漏洞环境**：DVWA/sqli-labs 是教科书，补 2–3 个真实 CMS 历史漏洞复现环境
  （Docker 化的 WordPress + 漏洞插件、ThinkPHP 注入 CVE 环境），
  这类环境的注入点位置/上下文/页面噪声是教科书模拟不出来的。
- **sqlmap 持续对拍**：`sqlmap-benchmark` 已有，固化成 CI 周跑 +
  「能力雷达图」自动生成（检出率/请求数/耗时/误报 4 轴，vs sqlmap 逐版本对比）。
- **误报猎场**：专门一批「长得像注入其实安全」的靶点
  （参数化但回显报错信息的、WAF 假阳性页、CDN 错误页），每次发版必过 0 误报。
- **靶场即文档**：每个 e2e 场景在报告/手册里可一键复现（pentest-lab 已带这个基因，推广到全部 lab）。

### E5. 架构与可维护性（P3，但不做会越欠越多）

- **`detect` 段状态收拢**：37 个散变量（`docs/runScanLoop-拆分方案-2026-09-12.md` 有方案），
  单独立项做 ScanContext 对象化，别顺手改。
- **payload 声明式 DSL**：`payloads/*.js` 目前是代码即数据，抽成 YAML/JSON DSL +
  校验器，让「加一条 payload」不需要改 JS，外部贡献者也能提交（配合 `payloadRegistry` 热加载）。
- **服务端 TS 化**：`docs/服务端类型化.md` 已有方案，按模块渐进迁移
  （engine 核心优先，api 层其次），类型能在重构 A 战线时挡掉一半回归。
- **大文件治理**：`docs/大文件拆分-五刀复盘-2026-09-21.md` 的拆分纪律固化为
  `arch-guard` 行数门禁。

## 八、红线与不做清单

1. **不谎报**：任何通道不可用时输出 `inconclusive` + 建议，永不输出「安全」（现有生命线，任何优化不得破坏）。
2. **默认只读**：写库/写文件/命令执行类动作必须显式开关 + 二次确认 + 报告留痕。
3. **授权先行**：scopeGuard / SSRF / 重定向逐跳校验是底线，任何「便利功能」不得绕过。
4. **不做的事**：
   - 不做 GUI 上堆「看起来专业」但无实测支撑的功能（每项能力必须有 e2e 真机背书）；
   - 不追求 tamper 数量超过 sqlmap（228 个已够，**增益率**才是 KPI）；
   - 11 个 DBMS 不假装支持，验证一个升档一个；
   - 不内置传播/爆破/批量打站功能（工具定位是授权检测，不是攻击平台）。
